# Шаг 1: годовщина мероприятия

Самый сильный сигнал из всех, что у нас есть. «В прошлом ноябре вы собирали
600 человек в таком-то зале» — повод проверяемый и конкретный. Всё остальное
(юбилей компании, вакансии, тендеры) слабее и подключается потом.

Смысл сигнала в сроке. Когда мероприятие анонсировано публично, площадка
забронирована два-четыре месяца назад — вы приходите к закрытой двери. Поэтому
скрипт смотрит не на анонсы, а на **прошлогодние** мероприятия и считает, когда
их повторят и когда про это писать.

## Что делает и чего не делает

Делает: берёт из Timepad прошедшие московские мероприятия за N лет, оставляет
крупные, группирует по организатору и месяцу, считает ожидаемую дату повторения
и окно контакта, печатает список по приоритету.

Не делает: ничего больше. Ни базы, ни писем, ни конвейера. Их имеет смысл
строить только после того, как окажется, что этот список осмысленный.

## Запуск

```bash
cd ~/finding
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python anniversary.py --years 2 --min-attendees 250
```

Всё. Одна команда, один вывод. Выглядит так:

```
Событий получено: 840
Разобрано: 812 (у 431 известно число участников)
Крупных (от 250 чел.): 96

Найдено ожиданий: 74, из них писать пора: 12

1. ООО Ромашка-Трейд  [ПИСАТЬ СЕЙЧАС]
   Было: «Конференция дистрибьюторов» — 2025-11-12, ~650 чел. (продано билетов)
   Повторяется 3 г.: 2023, 2024, 2025 — уверенность выше
   Ожидаем: ноябрь 2026. Уверенность 0.90
   https://example.timepad.ru/event/1001/
```

Полезные ключи:

| Ключ | Зачем |
|---|---|
| `--min-attendees 250` | порог масштаба; ниже мы проигрываем по локации, см. ниже |
| `--years 3` | сколько прошлых сезонов смотреть; больше — виднее повторы |
| `--horizon 180` | на сколько дней вперёд смотрим (столько же берём из прошлого) |
| `--keep-unknown` | оставить события, где число участников не отдалось |
| `--keep-venues` | оставить организаторов-площадок (по умолчанию отброшены) |
| `--csv out.csv` | выгрузить список |
| `--today 2026-11-01` | посчитать окна на другую дату, для проверки |
| `--raw` | сырой JSON первого события — понадобится, если что-то не сойдётся |
| `-v` | показывать ход постраничной выборки |

## Что нужно от вас

**1. Запустить и прислать вывод.** Это главное. Дальше решаем по факту, а не по
предположениям.

**2. Возможно, токен Timepad.** Скрипт сначала пробует без него. Если API ответит
401 или 403, он прямо это скажет — тогда нужен личный токен из кабинета Timepad
(раздел для разработчиков; актуальный порядок описан на dev.timepad.ru). Передать
можно двумя способами:

```bash
python anniversary.py --token ВАШ_ТОКЕН
# или
export TIMEPAD_TOKEN=ВАШ_ТОКЕН
```

**3. Решить про порог масштаба.** Сейчас 250 человек. Причина: на 100–150
площадка конкурирует с несколькими сотнями московских залов и проигрывает по
локации, а на 800–1500 конкурентов десятки, и там же работают её преимущества —
вход из МЦК прямо в ТРЦ и парковка торгового центра. Если считаете иначе —
скажите число, это один ключ.

## Если отказали в доступе

```bash
python anniversary.py --check
```

Делает три запроса по нарастающей — простейший без токена, простейший с
токеном, наш полный — и печатает статус каждого. Это отделяет «API вообще
требует токен» от «наш конкретный запрос не нравится»: в первом случае надо
идти за токеном, во втором чинить параметры, и путать их дорого.

## Если что-то не сойдётся

Я писал разбор ответа, **не имея доступа к Timepad**: из моего окружения нет
выхода в сеть, прокси режет внешние хосты. Структуру ответа я знаю в общих
чертах, но точные имена полей мог не угадать. Поэтому:

- **если в строке «у N известно число участников» стоит ноль** — поля называются
  иначе. Пришлите вывод `python anniversary.py --raw`, поправлю за минуту:
  вся разметка собрана в одном месте (`EVENT_FIELDS` и `parse_attendees`);
- **если событий получено ноль** — не тот период или город, попробуйте
  `--years 3` и `-v`;
- **если 401/403** — нужен токен, см. выше.

Число участников — самое хрупкое место. Timepad не отдаёт фактическую
посещаемость прошедших событий, поэтому скрипт берёт ближайшее к правде:
сколько билетов продано, иначе сколько мест заявлено. Не нашёл — пишет
«неизвестно» и не выдумывает. Выдуманное число попадёт в письмо и сожжёт лид.

## Почему запрос идёт по сезонам, а не «за два года подряд»

Первый живой прогон вернул ровно 1000 событий — потолок — и все за последние
две недели: сортировка по убыванию даты обрезала выборку с того конца, ради
которого всё затевалось. Прошлогоднего ноября скрипт не увидел вообще.

Теперь спрашивается не «всё за два года», а «тот же сезон год и два назад»:
стоя в конце июля, мы берём август–январь прошлых лет — именно их годовщина
придётся на ближайшие месяцы. Запрос выходит маленький, точный и покрывает
корпоративный сезон целиком. Если период всё же упрётся в потолок, скрипт
скажет об этом прямо: молчаливое обрезание — то, из-за чего первый вывод
и был обманчивым.

## Про организаторов-площадок

Timepad — билетная платформа, и её основная аудитория — культурные центры,
кинотеатры, театры, лектории. У них свой зал, наш они арендовать не будут,
а «330 мест» в их карточке — вместимость собственного помещения, а не масштаб
корпоративного мероприятия.

Такие организаторы распознаются по названию и отбрасываются, но их количество
печатается в сводке — эвристика грубая, и прятать её работу нельзя.
Посмотреть, кого отбросили: `--keep-venues`.

## Что решаем по результату

Список должен ответить на один вопрос: **есть ли в Москве достаточно компаний,
которые регулярно проводят мероприятия нашего масштаба и которых видно через
Timepad.**

- Если «писать пора» набирается хотя бы десяток осмысленных строк — сигнал
  рабочий, идём дальше: контакты, письма, регулярный прогон.
- Если строк единицы или организаторы сплошь агентства и площадки, а не
  заказчики — значит Timepad для этого сегмента слеп, и следующий шаг другой:
  страницы «прошедшие мероприятия» у площадок-конкурентов. Там заказчики
  перечислены прямым текстом.

Это и есть смысл шага: узнать это сейчас, а не после того, как построена
половина системы.

## Проверка кода

```bash
pip install -r requirements-dev.txt
pytest -q          # 23 теста, сеть не нужна
ruff check .
```

Тесты покрывают то, где ошибка дороже всего: расчёт даты повторения и окна
контакта (письмо не должно уходить после того, как зал выбран) и извлечение
числа участников (ничего не выдумывать).
