# Matchlab

Первый исследовательский прототип сервиса футбольных прогнозов. АПЛ, до матча,
рынок 1X2: победа хозяев, ничья, победа гостей. Веб-интерфейс и HTTP API,
реальные исторические результаты, воспроизводимая проверка модели и
необязательные объяснения через собственный Qwen.

## Быстрый запуск

Нужны Python 3.12 и доступ к PyPI и `raw.githubusercontent.com`. GPU приложению
не нужен: Qwen уже работает на отдельном сервере и доступен через SSH-туннель.

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

Скрипт установки создаёт `.venv`, устанавливает зафиксированные зависимости,
загружает сезоны 2020/21–2025/26 и проверяет модель на 2024/25 и 2025/26.
Повторный запуск обновляет эти сезоны атомарно; сохранённые прогнозы остаются.
При неудачной загрузке прежние данные сезона сохраняются. Частичная загрузка
завершается кодом 2, а не выдаётся за полный успех.

Сервис слушает `127.0.0.1:8080`. Интерфейс находится в `/`, документация API —
в `/docs`, готовность данных проверяется через `/api/health`. Адрес и порт можно
изменить переменными `MATCHLAB_HOST` и `MATCHLAB_PORT`. Аутентификация не
реализована: для публичного развёртывания нужен контролирующий доступ прокси.

Данные, сырые CSV, история прогнозов и отчёт лежат в `.local/` (исключено из Git).
Для постоянного хранилища задайте абсолютный путь `MATCHLAB_DATA_DIR` в `.env`.
Живые процессы и SSH-туннели нужно запускать после перезапуска сервера.

## Что работает

- Импорт завершённых матчей с проверкой дат, счёта, исходов и дублей.
- Вероятности 1X2, ожидаемые голы модели и пять наиболее вероятных счетов.
- Выбор даты: обучение использует результаты строго **до** выбранного дня;
  для будущей даты не используются результаты позднее сегодняшнего дня.
- Сравнение с вручную введёнными текущими коэффициентами: удаление маржи
  нормировкой обратных коэффициентов и `EV = p × coefficient − 1`.
- Сохранение прогнозов с версией модели, хешем набора, временем расчёта и
  периодом обучения. Исторические сценарии помечаются отдельно.
- Проверка на более поздних матчах, частотный базовый прогноз, log loss,
  Brier score, accuracy и диаграмма калибровки.
- Объяснение готового прогноза через OpenAI-совместимый API Qwen.

Выбранная пара команд — **ручной сценарий**, а не подтверждённая встреча в
расписании. Автоматический поток новостей, травм, составов, календаря и
коэффициентов пока не подключён. Интерфейс показывает возраст последних
результатов и предупреждает об устаревшей выборке. Историческая проверка
сама по себе не подтверждает преимущество над букмекерами или доходность.

## Подключение Qwen через существующий SSH-туннель

```bash
cp .env.example .env
```

Укажите в `.env` **локальный** адрес уже проброшенного порта и точный идентификатор
модели из ответа `GET /v1/models` вашего сервера. Для vLLM с туннелем на порту 23333:

```dotenv
QWEN_BASE_URL=http://127.0.0.1:23333/v1
QWEN_MODEL=QuantTrio/Qwen3.5-35B-A3B-AWQ
QWEN_TIMEOUT_SECONDS=90
QWEN_ENABLE_THINKING=false
QWEN_MAX_TOKENS=2048
```

При необходимости добавьте `QWEN_API_KEY` только в `.env` или окружение процесса.
Файл `.env` исключён из Git. Приложение читает его при старте, не перезаписывая
уже заданные переменные. Перезапустите приложение после изменения настроек.
Если туннель работает на хосте, запускайте приложение на том же хосте:
loopback-адрес внутри отдельного контейнера будет другим.

При нативном запуске через systemd имя `host.docker.internal` обычно не
разрешается: используйте адрес локального SSH-туннеля, как в примере выше.
Для проверки до перезапуска приложения выполните:

```bash
.venv/bin/python -m matchlab check-qwen
```

Команда проверяет `/models`, наличие настроенного идентификатора и один
настоящий запрос `/chat/completions`. Она не создаёт базу, не выводит ключ,
содержимое ответов или рассуждения модели. Успех означает проверенное соединение
и получение основного текста, а не проверенную точность объяснений.

`QWEN_ENABLE_THINKING=false` передаёт параметр
`chat_template_kwargs.enable_thinking=false`, поддерживаемый vLLM с шаблоном Qwen.
Это помогает избежать расходования лимита ответа только на рассуждения.
Для сервера, не поддерживающего этот параметр, оставьте переменную незаданной.
`QWEN_MAX_TOKENS` задаёт максимальную длину ответа. Ошибки подключения, HTTP,
неверного JSON, пустого ответа и исчерпания токенов сообщаются отдельно.

После успешной проверки примените изменения к сервису:

```bash
sudo systemctl restart matchlab
```

Наличие настроенного адреса не означает проверенное подключение: доступность
проверяется при запросе объяснения. Без Qwen вся статистическая часть работает.
Qwen получает готовые вероятности и период обучения, а также ваши необязательные
непроверенные заметки. Он не изменяет сохранённые вероятности. Программа не
получает новости автоматически и не считает заметки подтверждёнными фактами.
Ответ ИИ остаётся комментарием, фактическую точность которого следует проверять.

## Данные и обновление

Первоисточник: [Football-Data.co.uk](https://www.football-data.co.uk/englandm.php).
Если он недоступен, загрузчик использует
[datasets/football-datasets](https://github.com/datasets/football-datasets).
Зеркало указывает PDDL 1.0 для наборов европейских лиг; условия первоисточника
нужно учитывать отдельно при коммерческом распространении. Для каждого сезона
хранятся адрес источника, SHA-256 полученного CSV и время импорта.

Зеркало содержит результаты и статистику, но не букмекерские коэффициенты.
Даже при импорте полного Football-Data CSV существующие поля коэффициентов
не считаются историческими снимками с известным временем. Сравнение с рынком
в отчёте отключено. Коэффициенты закрытия нельзя использовать как сведения,
известные за сутки до матча. Ручной ввод фиксируется как полученный сейчас,
поэтому для расчёта на другую дату он запрещён.

В проверенной здесь загрузке: **2280 матчей, 12.09.2020–24.05.2026**.
Это исторический набор, а не актуальный календарь сезона 2026/27.

```bash
# Обновить определённый сезон, если он доступен у источника
.venv/bin/python -m matchlab download --seasons 2627

# По умолчанию download пробует последние семь сезонов, включая текущий
.venv/bin/python -m matchlab download

# Импортировать свой CSV формата Football-Data
.venv/bin/python -m matchlab import-csv /path/to/E0.csv --season 2627

# После любого изменения набора повторить проверку
.venv/bin/python -m matchlab backtest --seasons 2425 2526
.venv/bin/python -m matchlab status
```

Неудачное обновление не очищает базу. Отчёт с хешем, отличным от текущих данных,
перестаёт отображаться как актуальный. Повторный импорт тех же байтов не
инвалидирует отчёт.

## Модель и методика проверки

Независимые распределения Пуассона для голов хозяев и гостей. Обучаемые
параметры: общий уровень голов, преимущество своего поля, атака и защита команд.
Командные параметры регуляризованы; более свежие матчи имеют больший вес
(период полураспада 365 дней). Обучающее окно — 1095 дней. Для команды требуется
не менее пяти предыдущих матчей АПЛ, для обучения — не менее ста матчей.
Ожидаемые голы этой модели **не являются событийным xG**.

В проверке модель переобучается на первое число каждого месяца, используя
только более ранние результаты. Параметры фиксированы на весь проверяемый месяц.
Матчи команд с недостаточной историей пропускаются с явным счётчиком.
Нулевая проверка и отсутствующий запрошенный сезон завершаются ошибкой.
Базовая модель использует частоты 1/X/2 из того же обучающего окна, со сглаживанием.
Гиперпараметры заданы заранее; автоматического подбора на тестовых сезонах нет.

Результат текущего прогона на 2024/25 и 2025/26:

| Показатель | Пуассон | Частотная модель |
|---|---:|---:|
| Log loss, меньше лучше | 1.008 | 1.082 |
| Brier, сумма по трём исходам, шкала 0–2 | 0.604 | 0.655 |
| Верный наиболее вероятный исход | 49.9% | 41.8% |

Оценено 748 из 760 матчей, пропущено 12. Это сравнение двух статистических
моделей на истории, без рыночного базового прогноза. Калибровочная диаграмма
объединяет вероятности трёх классов по интервалам шириной 10%; это диагностика,
а не процедура подгонки вероятностей.

## Проверки и API

```bash
.venv/bin/python -m unittest discover -v
node --check matchlab/static/app.js  # необязательно для запуска, нужен Node
```

Дополнительная проверка реального интерфейса в Chromium (при запущенном сервисе
с загруженной историей):

```bash
.venv/bin/python -m pip install -r requirements-browser.txt
# Если системного Chromium нет:
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser_smoke.py
```

При необходимости можно явно передать `--chromium /usr/bin/chromium`.
Проверяются прогноз, ручные коэффициенты, ошибки ввода, исторический сценарий,
защита от запоздавшего ответа на изменённый выбор и мобильная ширина.

Тесты проверяют исключение будущих и одновременных результатов, границы
обучения, вероятности, атомарность импорта, валидацию API, сохранение прогнозов,
устаревание отчёта и контракт Qwen. Запросы к Qwen в тестах подменяются;
это не подтверждает доступность реального сервера.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Готовность: 503, пока загружено меньше 100 матчей |
| GET | `/api/status` | Происхождение, даты данных, наличие конфигурации Qwen |
| GET | `/api/teams?as_of=2026-05-01` | Команды с достаточной историей |
| POST | `/api/forecast` | `home`, `away`, `as_of`, необязательный `odds` с `home/draw/away` |
| GET | `/api/forecasts` | Последние 20 сохранённых расчётов |
| GET | `/api/backtest` | Актуальный отчёт с совпадающим хешем набора |
| POST | `/api/explain` | `forecast_id`, необязательные `notes` |

Дальнейший этап — подключить календарь и провайдера коэффициентов, собирать
снимки с отметками времени, затем провести проспективную проверку прогнозов.
Для него понадобятся выбранный источник и его доступ; ключи передаются через
переменные окружения, не через репозиторий.
