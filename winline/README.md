# Матчи и коэффициенты Winline

Отдельный Python-сборщик публичных данных сайта и SQLite-база для быстрых локальных запросов. Модуль автономен и не меняет сборщики или API Matchlab.

## Что собрано и как это работает

Сборщик открывает Winline в чистом Chromium без аккаунта. Бинарный поток WebSocket декодирует собственный клиент сайта `window.apiWlb`; сборщик читает его коллекции, включая события, не показанные на главной странице. Дополнительные обычные рынки прематча запрашиваются через публичный `EventService.getPluses`, архив результатов — через `ResultService`. Это внутренний интерфейс сайта, а не документированный стабильный API: изменение клиента может потребовать обновления адаптера `browser.py`.

В базе есть:

- все события текущей коллекции сайта, без фильтра по спорту: участники, ID, спорт, страна, турнир, дата, live-признак;
- текущие счёт, счёт по периодам, часы/стадия игры и остальные исходные поля;
- линии рынков, параметры, массивы коэффициентов и соответствующие подписи исходов;
- история **наблюдавшихся изменений** событий и линий с момента запуска сборщика;
- доступные архивные результаты, отдельно от текущих событий;
- справочники, исходные JSON и отчёт об успешных/неуспешных запросах.

Папка `data/` содержит результаты и исключена из Git:

```text
data/
  winline.sqlite3           # Основная база, читается sqlite3 и Python
  snapshots/
    capture-<id>.json.gz    # Последний исходный снимок коллекций каждого запуска
  events.json              # Пример выгрузки текущих событий, создаётся командой query
  coverage.json            # Сводка фактического сбора
  audit.json               # Целостность, охват и сравнение с числами источника
```

## Установка и запуск

Из корня репозитория:

```bash
pip install -r winline/requirements.txt
python -m playwright install chromium
python winline/collect.py
python winline/supplemental.py
```

По умолчанию сборщик получает текущий поток, запрашивает дополнительные обычные рынки каждого прематч события с объявленными рынками, выгружает доступный архив до 30 дней для каждого спорта и затем наблюдает изменения ещё 20 секунд. Полный проход занимает несколько минут или дольше в зависимости от числа событий и скорости источника. Прогресс выводится каждые 100 событий и 50 архивных запросов. Снимки и результаты сохраняются по ходу работы, база не перезаписывается.

Если Chromium уже установлен:

```bash
python winline/collect.py --chromium /usr/bin/chromium
python winline/supplemental.py --chromium /usr/bin/chromium
```

Быстрое обновление текущего потока без архива и дополнительных запросов:

```bash
python winline/collect.py --no-expand-markets --history-days 0 --seconds 30
```

Наблюдение live в течение часа со снимками раз в 10 секунд:

```bash
python winline/collect.py --no-expand-markets --history-days 0 --seconds 3600 --interval 10
```

Запускайте один сборщик на базу. Повторный запуск обновляет текущие записи и добавляет историю только при изменении содержимого. `--event-limit 10` ограничит дополнительные рынки первыми 10 событиями для диагностики. `--market-batch-size 1` включает последовательные запросы (по умолчанию максимум 4 одновременно). `--request-delay` задаёт паузу между стартами запросов; `--raw-frames` дополнительно сохраняет исходные сообщения WebSocket.

## Быстрые запросы

```bash
python winline/query.py stats
python winline/query.py coverage
python winline/audit.py --output winline/data/audit.json
python winline/query.py events --live --limit 10
python winline/query.py events --sport 1 --team "Зенит"
python winline/query.py results --sport 1 --limit 10
python winline/query.py odds --event 17119181
python winline/query.py supplemental --event 17119181
python winline/query.py history --event 17119181
python winline/query.py history --event 17119181 --line 1577311450
```

ID в примерах относятся к пробной выгрузке; актуальный ID берите из `events`. `--team` ищет часть названия без учёта регистра, включая кириллицу. Временные фильтры `--from-date` и `--to-date` относятся к времени начала в UTC; верхняя граница исключается. Например:

```bash
python winline/query.py events --from-date 2026-11-09 --to-date 2026-11-10
python winline/query.py sql "SELECT id,name FROM sports WHERE name<>'' ORDER BY name"
python winline/query.py sql "SELECT * FROM collection_runs ORDER BY capture_id DESC LIMIT 5"
```

JSON по умолчанию выводится в stdout, вложенные JSON-поля преобразуются в объекты/массивы. Экспорт:

```bash
python winline/query.py --output winline/data/events.json events --limit 100000
python winline/query.py --format csv --output winline/data/results.csv results --limit 1000000
```

Из Python, также без сети:

```python
from winline.query import read_query

matches = read_query(
    "SELECT * FROM matches WHERE sport_id=? AND is_live=1 AND present_in_latest_snapshot=1",
    (1,),
)
odds = (
    read_query(
        "SELECT * FROM latest_odds WHERE event_id=? AND present_in_latest_snapshot=1",
        (matches[0]["id"],),
    )
    if matches
    else []
)
```

`query.py` открывает базу только для чтения, включая произвольный SQL. Готовые запросы находятся в `examples.sql`.

## Таблицы и смысл полей

| Таблица / представление | Содержимое |
|---|---|
| `matches` | События с названиями спорта, страны и турнира |
| `events`, `event_history` | Последние состояния и изменения событий |
| `latest_odds`, `lines`, `line_history` | Последние наблюдавшиеся линии и история |
| `results`, `result_history` | Завершённые события и исправления результатов |
| `supplemental`, `supplemental_history` | Отдельные ответы рынков игроков и долгосрочных исходов |
| `sports`, `countries`, `championships` | Справочники |
| `captures`, `collection_runs`, `snapshots` | Время, настройки, статус и размеры выгрузок |
| `result_catalog` | Дни и виды спорта, объявленные доступными архивом |
| `result_requests`, `market_requests` | Выполненные запросы, число строк и ошибки |
| `frames` | Необязательное сохранение исходного бинарного потока |

В линиях `odds_json` — массив `V` источника; позиция в `labels_json` соответствует той же позиции в массиве коэффициентов. `parameter` — исходный параметр рынка (`koef`), например `2.5` или `1/18.5`, **не сам коэффициент ставки**. `market_template` может содержать обозначения `@NP@`, `[a]` и другие шаблоны сайта; параметры сохраняются отдельно, чтобы не выдавать неверно расшифрованный рынок. Полная структура доступна в `raw_json`.

Время начала приводится браузером к ISO UTC. Служебные доли секунды (`.999`, `29.999`), добавляемые клиентом сайта, сохранены как есть; это не точность измерения времени матча. `last_seen` означает время чтения локального состояния клиента, а не время изменения котировки на сервере.

`present_in_latest_snapshot` показывает присутствие записи в последнем снимке. Отсутствие в потоке не считается подтверждением окончания матча. Для результатов используется отдельный ключ: `results.radar_id` и `events.radar_id` принадлежат одной системе радара, но `events.id` — другой идентификатор. Автоматически объединять эти поля нельзя.

## Проверка охвата и ограничения

Статус `collection_runs.status='complete'` означает выполнение **запланированных этим запуском запросов**, а не подтверждение полноты всего сайта. Сверяйте `planned_*_requests` с фактическим числом строк в таблицах запросов и смотрите ошибки. Остановленный/неполный запуск сохраняет уже полученные данные. Если ответ архива задержался, серия запросов останавливается, чтобы не отнести поздний ответ к другому спорту.

Сайт объявил в пробной проверке архив примерно за последние 30 дней. Произвольная история за годы и прошлые коэффициенты из этого интерфейса не подтверждены. Коэффициенты накапливаются с момента наблюдения. Снимки фиксируются с заданным интервалом, поэтому изменения между ними могут быть пропущены. Редкие виды спорта могут отсутствовать в текущей коллекции, если у них нет событий. Новые события, появившиеся после начала прохода дополнительных рынков, попадут в поток, но их дополнительные рынки будут запрошены при следующем полном запуске.

`supplemental.py` отдельно обходит объявленные клиентом режимы `hasPlayers()` и `hasOutrights()` для прематча и вызывает `getPlayersLines` / `getOutrights`. Их ответы сохраняются в `supplemental` по родительскому ID события и типу запроса, история — в `supplemental_history`. В режиме `players` JSON содержит линии с именем игрока; в `outrights` — дочерние события с их линиями. Пустой массив означает подтверждённый пустой ответ. Для быстрого пробного запуска есть `--limit 3`. Эти данные читаются командой `query.py supplemental`, а не смешиваются с обычными линиями. Закрытые данные и внешние виджеты статистики не входят в сбор. Покрытие ограничено проверенными публичными интерфейсами, а не всеми внутренними данными Winline.

Браузер использует унаследованный HTTPS-прокси. В управляемой среде доверие к её настроенному CA ограничено SPKI-ключом этого CA в отдельном Chromium; общий TLS-контроль не отключается. Для другого прокси можно явно задать `--proxy-ca /path/to/ca.pem`. `--ignore-https-errors` оставлен только для диагностики и не использовался в полном сборе.

## Тесты

```bash
python -m unittest winline.test_storage -v
```

Тесты проверяют историю без дубликатов, переход в live, отдельные ключи линий, исправления результатов, отсутствие выдуманного статуса завершения и соединение SQL только для чтения.
