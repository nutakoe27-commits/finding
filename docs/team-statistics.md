# Статистика участников для ИИ-разбора

Текущий вариант **без Mac**: [prognozich-online.md](prognozich-online.md).
Браузерный сборщик статистики работает на сервере V100. Winline открывает
статистику во фрейме StatsHub/Sportradar; ранее этот источник ответил серверу
`Access Denied`. Рынки и статистика обновляются независимо, а ограничение доступа
показывается в карточке. Автоматический обход блокировки не выполняется.

Подготовленная версия службы использует обычный видимый Chromium в отдельном виртуальном дисплее Xvfb,
без доступа к пользовательскому рабочему столу или профилю браузера. Для этого
на сервере нужны системные пакеты `xvfb` и `xauth`. Режим не гарантирует доступ:
при ответе 403 сборщик сохраняет паузу и последнее успешное наблюдение.
GLX на виртуальном дисплее отключён: на сервере с NVIDIA его инициализация
вызывала сбой Xvfb. Сообщения сборщика доступны в журнале службы.
Служба ограничена двумя логическими ядрами CPU (`CPUQuota=200%`) и 1024 МиБ RAM;
она работает с пониженным приоритетом, оставляя ресурсы нейросети.
Массового сбора подробной статистики нет. При нажатии «ИИ-аналитика» сайт
ставит в очередь только выбранный матч; служба проверяет задания примерно раз
в две секунды и обрабатывает их последовательно. ИИ-разбор начинается после
завершения задания либо после ожидания до двух минут. При недоступности источника
используются имеющиеся данные и показывается ограничение. Повторные запросы
одного матча объединяются. При блокировке сохраняется пауза источника.
Поток матчей, live-коэффициентов и сбор архива работают отдельно.

Связь берётся из настоящей ссылки или явно обозначенной кнопки статистики
в карточке события. ID линии и ID `/stats/match/…` различаются. Числа не
подставляются друг вместо друга. Неоднозначная ссылка не отправляется в очередь.
Открытие кнопки статистики не меняет время наблюдения коэффициентов.
Это обзор и сравнение участников конкретного матча, а не общий профиль игрока
или одна фиксированная страница для всех. Для каждой карточки используется её
собственная кнопка «Статистика», в том числе расположенная вне старого заголовка.
Если цены прочитаны частично, подтверждённую ссылку можно сохранить отдельно
для той же пары участников, сохранив прежние цены и их время.
Диагностика без `--url` ищет кнопку текущего матча футбольной линии; фиксированного
ID по умолчанию нет. Для выбранного матча используется его собственная ссылка.

Сборщик читает только фрейм провайдера с соответствующим ID. Реклама и
оболочка Winline не считаются статистикой. По наблюдаемым заголовкам `h3`
извлекаются форма и показатели из заголовка матча, сезонная статистика,
таблица, личные встречи и последние матчи. Текст сохраняется с названиями
разделов, временем и источником; неизвестные числовые колонки не превращаются
в придуманные метрики.

Сборщик также наблюдает JSON-ответы, которые сам виджет получает в браузере:
отдельных запросов к закрытому адресу он не делает. Матч проверяется по ID
виджета, а разные ID одной команды связываются только через наблюдённую запись
этого же матча с совпадающими ID обеих сторон. Если у каждого участника найден
ещё хотя бы один идентифицируемый матч, можно передать предварительный снимок;
подробные разделы продолжают собираться следом. Уже сохранённый подробный
снимок предварительным не перезаписывается. Списки могут содержать текущие
и будущие встречи, поэтому сам факт наличия записи не подтверждает результат.
Это не гарантирует мгновенную подготовку полного разбора или покрытие всех видов спорта.

Для примера пользователя `72334410` источник показывал завершённый матч
«Спартак — Акрон» 2:1. Статус `finished` передаётся в ИИ: итог и включающие
его показатели нельзя выдавать за предматчевое знание. Независимая футбольная
оценка в таком контексте отключается. Индекс «Общая форма 80/100» явно
отличается от вероятности победы 80%. Данные статистики не добавляются в
обучающую выборку и исторический тест модели.

## Обновление сервера

На VPS:

```bash
cd /root/matchlab
git pull --ff-only origin main &&
sudo systemctl restart matchlab.service
```

На сервере сборщика:

```bash
sudo apt-get update && sudo apt-get install -y xvfb xauth
cd ~/matchlab-scraper-src
git pull --ff-only origin main &&
sudo bash scripts/install_server_statistics.sh
```

Установщик перезапускает только `matchlab-statistics.service` и использует
существующий туннель. `matchlab-crawler`, модель и другие проекты не меняются.

В карточке матча кнопка «Обновить данные» ставит в очередь отдельную задачу:
служба статистики открывает именно страницу этого события, проверяет живой поток
коэффициентов и обновляет снимок рынков, затем запрашивает статистику по найденной
ссылке. Очередь проверяется примерно раз в две секунды между другими задачами;
время ответа зависит от источника и загрузки. Повторные нажатия объединяются,
а после завершения действует 30-секундный интервал на событие.
Если источник заблокировал статистику, для всех событий действует часовая пауза, сохраняется
последний успешный снимок и интерфейс показывает ограничение. Это не гарантирует
обновление всех страниц каждую минуту.

## Свежесть и ошибки

Успешные страницы не проверяются повторно без нового запроса пользователя.
Пауза при блокировке длится час. Время чтения каждой страницы
сохраняется отдельно от времени коэффициентов. После часа снимок помечается
устаревшим. Ошибка обновления не удаляет последний успешный снимок.

`receiver_unavailable` относится к приёмнику на VPS и туннелю, а не к запрету
провайдера статистики. После сбоя сборщик ждёт 5, 10, 20, 40, затем до 60 секунд
между попытками; получение ошибок не запускает частый цикл запросов.
В журнале указаны `operation`, `error_type`, `http_status` для HTTP-ошибок и
`retry_in_seconds`. Тексты ответов, заголовки и ключ не печатаются.
У `blocked` дополнительно выводится `source_blocked_until`: время окончания
паузы провайдера, которое сохраняется на VPS и не сбрасывается переустановкой.

В карточке есть раскрываемый блок «Статистика участников». В метаданных ответа
ИИ указано время использованного снимка или отсутствие статистики в разборе.
Новые данные меняют ключ кэша, поэтому прежний ответ без статистики не подменяет
новый разбор. Контекст ограничен по размеру, а непереданные разделы не считаются
проанализированными.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/bookmakers/events/ID/statistics/request` | Запрос статистики выбранного матча авторизованным пользователем |
| GET | `/api/bookmakers/events/ID/statistics/request/JOB` | Состояние задания |
| POST | `/api/bookmakers/refresh/claim`, `/finish` | Приём и завершение задания службой (`kind=statistics`) |
| GET | `/api/bookmakers/statistics/queue` | Совместимость со старой службой; очередь всегда пуста |
| POST | `/api/bookmakers/statistics/ingest` | Защищённая доставка снимка/статуса |
| GET | `/api/bookmakers/events/ID/statistics` | Сохранённая статистика и состояние ссылки |

Приём задания службой и доставка доступны только через loopback с ключом сборщика.
Аналогичные пользовательские адреса есть для `/api/archive/events/ID`.
Проверяются
ID события, исходная ссылка, ID статистики, домен фрейма, время, размер и состояние.
Страница `Access Denied` не принимается как статистические факты.

Сборщик также распознаёт видимые разделы с заголовками «Статистика матча»,
«Лучшие игроки», «Сезонная форма» и аналогичными названиями и передаёт их в контекст ИИ целиком в пределах общего
лимита снимка. Поддержка этих заголовков проверена на тестовом HTML; пока
провайдер отвечает 403, фактическую разметку и состав полей конкретного матча
проверить нельзя. При доступе к виджету может потребоваться доработка вкладок
и селекторов. Самостоятельно доступ к заблокированному источнику это не даёт.
Сборщик читает вкладку обзора и переходит по явно найденным в виджете ссылкам
на отчёт и статистику того же матча. Список прочитанных вкладок и время каждого
раздела сохраняются; недоступные вкладки не считаются прочитанными. Варианты
сезонных фильтров «Итоги / За матч / Серия» и «Общее / Хозяева / Гости»
сборщик пробует переключать в рамках соответствующего блока и сохраняет только
подтверждённые `aria-pressed` варианты, указывая неполное покрытие. Фильтры
таблицы и игроков пока не переключаются. Переходы и фильтры проверены на тестовой странице.
9 ноября 2026 года отдельная диагностика Chromium под системной учётной записью в
Xvfb получила от виджета HTTP 200 и увидела девять заголовков. Сам сборщик и
переключение реальных вкладок и фильтров после развёртывания ещё нужно проверить.

Независимо от виджета поток Winline для футбольных live-событий может отмечать
наличие удаления у команды. Передаётся только положительная отметка без числа
карточек, имени игрока и времени удаления; отсутствие отметки не означает, что
удалений не было. Другие виды спорта не используют эту интерпретацию полей.
