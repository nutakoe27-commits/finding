# Статистика участников для ИИ-разбора

Winline открывает статистику во фрейме StatsHub/Sportradar. На сервере
сборщика он возвращал `Access Denied`; отдельная проверка на Mac прочитала
реальную страницу. Поэтому коэффициенты собираются на прежнем сервере,
а статистика — отдельным лёгким браузерным сборщиком на Mac.

Связь берётся из настоящей ссылки или явно обозначенной кнопки статистики
в карточке события. ID линии и ID `/stats/match/…` различаются. Числа не
подставляются друг вместо друга. Неоднозначная ссылка не отправляется в очередь.
Открытие кнопки статистики не меняет время наблюдения коэффициентов.

Сборщик читает только фрейм провайдера с соответствующим ID. Реклама и
оболочка Winline не считаются статистикой. По наблюдаемым заголовкам `h3`
извлекаются форма и показатели из заголовка матча, сезонная статистика,
таблица, личные встречи и последние матчи. Текст сохраняется с названиями
разделов, временем и источником; неизвестные числовые колонки не превращаются
в придуманные метрики.

Для примера пользователя `72334410` источник показывал завершённый матч
«Спартак — Акрон» 2:1. Статус `finished` передаётся в ИИ: итог и включающие
его показатели нельзя выдавать за предматчевое знание. Независимая футбольная
оценка в таком контексте отключается. Индекс «Общая форма 80/100» явно
отличается от вероятности победы 80%. Данные статистики не добавляются в
обучающую выборку и исторический тест модели.

## Обновление сервера

На VPS:

```bash
cd /root/matchlab
git pull --ff-only origin main
systemctl restart matchlab.service
```

На сервере сборщика:

```bash
cd ~/matchlab-scraper-src
git pull --ff-only origin main
sudo systemctl stop matchlab-crawler.service
sudo bash scripts/install_market_crawler.sh --api-url http://127.0.0.1:18081 --sports all
```

Сборщик доставляет рынки и связь со статистикой. Сама страница статистики на
этом сервере не опрашивается повторно после обнаруженного ограничения доступа.
Остальные службы, сервер модели и существующие туннели не перенастраиваются.

## Сбор статистики с Mac

Используйте каталог, где выполнялась успешная диагностика. В выводе пользователя
это `~/matchlab-collector`; если клонировали в `~/matchlab-statistics`, замените
первую строку.

```bash
cd ~/matchlab-collector
git pull --ff-only origin main
.venv/bin/python -m pip install -r requirements-server-scraper.txt
.venv/bin/python scripts/configure_statistics_client.py --api-url http://127.0.0.1:18082
```

Нужен Python 3.10+. Chromium уже установлен предыдущей диагностикой. Скрипт
настройки получает по обычному SSH только существующий ключ приёмника и
сохраняет его в `.local/statistics-client.json` с правами 600. Ключ не печатается,
файл исключён из Git; передавать его в чат не нужно. Конфигурация VPS и SSH-ключи
этим скриптом не меняются.

В отдельном терминале Mac оставьте работать выделенный локальный туннель:

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18082:127.0.0.1:8080 root@89.111.143.45
```

В терминале проекта запустите сбор:

```bash
.venv/bin/python -m matchlab.statistics_worker
```

Открывается отдельный видимый Chromium без доступа к вашему обычному профилю.
Он последовательно читает задачи с VPS и доставляет статистику. Интервал
проверки очереди — 60 секунд, до пяти страниц за цикл. Циклы не накладываются.
Для разовой проверки одной страницы используйте `--once --batch-size 1`.
Остановить сбор можно через Ctrl+C.

Mac и SSH-туннель должны оставаться включёнными. При выключенном Mac основной
сервер продолжает обновлять коэффициенты, а ИИ показывает, использовалась ли
сохранённая статистика. Пустая очередь с `linked_events=0` означает, что
обновлённый сборщик ещё не доставил ссылки статистики. Это не успешный сбор
статистики.

## Свежесть и ошибки

Очередь включает события, наблюдавшиеся в последние сутки. Успешные страницы
проверяются повторно через 15 минут, блокировка — через час, пустая страница —
через 30 минут, прочая ошибка — через 10 минут. Время чтения каждой страницы
сохраняется отдельно от времени коэффициентов. После часа снимок помечается
устаревшим. Ошибка обновления не удаляет последний успешный снимок.

В карточке есть раскрываемый блок «Статистика участников». В метаданных ответа
ИИ указано время использованного снимка или отсутствие статистики в разборе.
Новые данные меняют ключ кэша, поэтому прежний ответ без статистики не подменяет
новый разбор. Контекст ограничен по размеру, а непереданные разделы не считаются
проанализированными.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/bookmakers/statistics/queue` | Защищённая очередь связанных событий |
| POST | `/api/bookmakers/statistics/ingest` | Защищённая доставка снимка/статуса |
| GET | `/api/bookmakers/events/ID/statistics` | Сохранённая статистика и состояние ссылки |

Очередь и доставка доступны только через loopback с ключом сборщика. Проверяются
ID события, исходная ссылка, ID статистики, домен фрейма, время, размер и состояние.
Страница `Access Denied` не принимается как статистические факты.
