# Будущие матчи, Live и история в сервисе

Основная SQLite-база остаётся на постоянно работающем сервере нейросети:
`/var/lib/winline-archive/winline.sqlite3`. Новая служба `winline-archive-sync`
передаёт компактный поток событий и историю результатов на VPS через уже
настроенный исходящий SSH-туннель `127.0.0.1:18081`. Прямой SSH-доступ к серверу
нейросети из чата не нужен. Команды для него выполняются через приложение
«Ассистент». GPU и открытый входящий порт сборщику не требуются.

На VPS данные принимаются в отдельные таблицы существующей базы Matchlab.
Браузер пользователя обращается к VPS. Большая исходная база, сырые ответы,
копии и ключи не попадают в Git. Службы модели, прежних сборщиков и туннеля
сохраняют свои настройки.

## Что и как обновляется

| Данные | Обновление |
| --- | --- |
| Будущие и Live-события всех полученных видов спорта, счёт, стадия, основной рынок | Чтение состояния подключённого клиента Winline примерно каждые 10 секунд |
| Дополнительные обычные рынки открытого матча | Запрос источнику примерно каждые 20 секунд, до 4 недавно открытых событий одновременно |
| Передача на VPS | Цикл каждые 10 секунд после завершения предыдущего |
| Интерфейс | Опрос каждые 10 секунд, пока вкладка видима |
| Свежие результаты | Последний доступный день каждого спорта при коротком проходе, обычно через несколько минут |
| Полный обход обычных рынков и результатов | Первый проход примерно за 30 доступных дней, затем последние 2 дня; не чаще раза в 6 часов после завершения |
| Дополнительные ответы игроков и долгосрочных рынков | Отдельный проход примерно раз в 6 часов; сырые ответы доступны в локальной базе |

Это периодические наблюдения, а не гарантия доставки каждого изменения.
Полная задержка складывается из задержки источника, сбора, передачи и браузера:
обычно десятки секунд, но при обходе, переподключении или ошибках больше.
Долгий полный обход и архивные запросы продолжают сохранять текущие снимки.
В полном проходе история результатов запрашивается перед дополнительными
рынками. Служба делает частые облегчённые снимки событий и основных рынков;
дополнительные линии сохраняются для открытых матчей и ответов полного обхода.
Ранее накопленные линии и их история остаются в SQLite. Небольшое число линий
в очередном снимке не означает удаления остальных записей.
Первичная передача истории идёт ограниченными порциями между передачами потока.
Все дополнительные рынки всех событий каждые 10 секунд не запрашиваются.
Имена рынков и исходов формирует публичный клиент Winline; нерасшифрованные
шаблоны не показываются как готовые условия. Данные игроков и вложенных
долгосрочных ответов пока не включены в интерфейс обычных рынков.

Время «наблюдения» означает чтение состояния клиента, а не момент изменения
на сервере букмекера. У каждого рынка есть отдельное время. Через 45 секунд
снимок/рынок помечается устаревшим; через 90 секунд без сообщения передачи
соединение считается потерянным. Последнее наблюдение остаётся доступным.
Исчезновение события само по себе не означает его завершение. Подтверждённый
результат привязывается по виду спорта, участникам и времени начала.

## 1. Обновить VPS сайта

Выполнять на VPS `89.111.143.45` в существующем каталоге сайта:

```bash
cd /root/matchlab
git pull --ff-only origin main

# Проверить и обновить только правила API в существующем виртуальном хосте.
# Сертификаты, HTTPS, ACME, upstream и другие сайты сохраняются.
sudo .venv/bin/python scripts/update_archive_nginx.py --check
sudo .venv/bin/python scripts/update_archive_nginx.py

sudo systemctl restart matchlab.service
curl -fsS http://127.0.0.1:8080/api/archive/status
```

Новые Python-зависимости для VPS не нужны. При запуске создаются только новые
таблицы; существующие матчи, разборы и настройки модели сохраняются.
`update_archive_nginx.py` делает копию конфигурации, выполняет `nginx -t` и
перечитывает Nginx; при ошибке восстанавливает прежний файл. Скрипт работает
только с конфигурацией, ранее созданной Matchlab. Если он сообщает о другой
конфигурации, её нельзя перезаписывать шаблоном: в существующем виртуальном
хосте нужны запрет публичных `/api/bookmakers/archive/ingest` и
`/api/bookmakers/archive/watch`, а также тот же лимит ИИ-запросов для
`/api/archive/events/ЧИСЛОВОЙ_ID/explain`, что уже есть у прежних разборов.
Не запускайте HTTP-установку домена заново поверх настроенного HTTPS.

До включения передачи ответ с `available: false` и `connected: false` ожидаем.
Ключ `BOOKMAKER_INGEST_TOKEN` используется прежний; создавать новый не нужно.

## 2. Обновить сервер нейросети

Открыть терминал сервера через приложение «Ассистент», под пользователем `user`:

```bash
cd ~/matchlab-scraper-src
git pull --ff-only origin main

# Обновить свой сборщик с сохранением рабочей базы и расписания.
sudo bash scripts/install_winline_archive.sh --dry-run
sudo bash scripts/install_winline_archive.sh

# Проверить прежний исходящий туннель к VPS.
sudo systemctl is-active matchlab-scraper-tunnel.service
curl -fsS http://127.0.0.1:18081/api/archive/status

# Установить отдельную передачу архива и потока.
sudo bash scripts/install_winline_archive_sync.sh --api-url http://127.0.0.1:18081
```

Нужен Python 3.11+. Если системный Python старее, добавьте к обеим командам
базового установщика `--python /usr/bin/python3.12` с существующим путём.
Передача устанавливается после успешной проверки нового защищённого API VPS
с существующим ключом `/etc/matchlab-scraper-token.env` (`root`, права `600`).
Если туннеля или ключа нет, сначала выполните их существующую настройку по
[server-scraper.md](server-scraper.md); повторно создавать ключ не следует.

Базовый установщик кратко останавливает только `winline-archive`, обновляет его
код/окружение и проверяет Winline в отдельной `probe.sqlite3`. Проверка может
занять несколько минут. Если она не прошла, смотрите её вывод; не запускайте
второй экземпляр сборщика поверх службы. Повторная установка не удаляет рабочую
базу. Первичная синхронизация уже накопленной истории может идти несколько минут
и дольше; будущие и Live-матчи появляются независимо от её завершения.

## 3. Проверить оба сервера и интерфейс

На сервере нейросети:

```bash
sudo systemctl status winline-archive winline-archive-sync --no-pager
sudo cat /var/lib/winline-archive/status.json
sudo cat /var/lib/winline-archive/sync-status.json
sudo journalctl -u winline-archive-sync -n 40 --no-pager
```

`status.json: state=collecting` означает, что сбор идёт. Это нормально и при
длительном полном проходе. В `sync-status.json` ожидаются `state=ok`, свежее
`source_at`, число `events`, курсор и уменьшающийся `pending`. `waiting_data`
означает, что первый снимок ещё не появился. `error_type` и журнал позволяют
отличить отказ API/туннеля от проблемы локальной базы, не печатая ключ.

На VPS:

```bash
curl -fsS http://127.0.0.1:8080/api/archive/status
curl -fsS 'http://127.0.0.1:8080/api/bookmakers/events?include_started=true&phase=live&limit=3'
curl -fsS 'http://127.0.0.1:8080/api/archive/results?limit=3'
```

Когда всё работает: `available: true`, `connected: true`, `source_stale: false`;
`stored_results` растёт, а `sent_cursor` догоняет `source_cursor`. При долгом
первичном проходе история может ещё не охватывать нужную команду. Пустой Live
список также возможен, если в полученной коллекции сейчас нет Live-событий.
`unidentified_results` считает записи источника без даты или участников:
они сохраняются как наблюдения, но не выдаются за результаты матчей.

На `https://prognozich.online`:

1. «Матчи» → «Предстоящие» / «Live» / «Все». Live показывает полученные счёт
   и стадию игры. Значения обновляются автоматически на открытой вкладке.
2. Открыть матч → рынки и время каждой котировки, «История участников» и
   личные встречи. Дополнительные рынки могут появиться после следующего
   цикла передачи. Для ручного запроса есть кнопка обновления.
3. «Получить разбор ИИ» → Qwen получает выбранные рынки, текущий счёт/стадию
   и найденные предыдущие результаты; также используется ранее собранная
   статистика провайдера, если подтверждены участники, спорт и время встречи.
   Изменение рынка, счёта или истории
   создаёт новую версию разбора; уже сохранённый текст сам не переписывается.
4. «Архив» → поиск по участнику/турниру, фильтр спорта и страницы результатов.

История сопоставляется по точным нормализованным именам внутри одного спорта,
с проверкой выбранного события и времени. Неоднозначные псевдонимы не
склеиваются. В контекст попадают до 5 последних результатов каждого участника
и до 3 личных встреч, сыгранных до начала анализируемого матча и известных на
момент запроса. Для исторической проверки дополнительно учитываются время
наблюдения источником и время получения VPS, чтобы позднее исправление счёта
не становилось якобы заранее известным. Отсутствующие результаты обозначаются
как недоступные. Это контекст для ИИ, а не обучение весов нейросети и не
подтверждение точности прогнозов. Независимая вероятностная модель для всех
видов спорта не добавляется автоматически.

## Диагностика и восстановление передачи

- `HTTPStatusError`: проверить, что VPS обновлён, туннель активен, ключ
  соответствует прежнему ключу приёмника; не выводить файл ключа в чат.
- `source_stale: true` при `connected: true`: передача работает, но сборщик
  давно не получил свежий снимок; смотреть журнал `winline-archive`.
- `connected: false`: проверить службу передачи, туннель и приёмник VPS.
- `cursor: 0`, `pending: 0` в `sync-status.json`: у источника ещё нет версий
  результатов для отправки, это не признак завершившейся загрузки истории.
  После начала запросов архива `cursor` должен начать увеличиваться.
- Накопленный архив и копии остаются на нейросервере; резервные копии описаны
  в [winline-archive-server.md](winline-archive-server.md).

Если база VPS восстановлена из старой копии или создана заново и нужно повторить
передачу истории, выполнить **на сервере нейросети**:

```bash
sudo systemctl stop winline-archive-sync.service
sudo mv /var/lib/winline-archive/sync-state.json /var/lib/winline-archive/sync-state.before-replay.json
sudo systemctl start winline-archive-sync.service
```

Это сбрасывает только курсор передачи. Исходную SQLite и `schedule.json`
не удалять. Повторная доставка объединяет результаты по ключу встречи и
сохраняет версии. Чтобы отключить только передачу, используйте
`sudo systemctl disable --now winline-archive-sync.service`.
