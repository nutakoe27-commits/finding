# Независимая оценка и популярные рынки Winline

Текущая версия — `transparent-forecast-and-evaluation-v19`. Коэффициенты Winline
не используются в расчёте и не передаются Qwen. Они остаются в каталоге и архиве
для просмотра. Вероятности вычисляет сервер, а Qwen подробно объясняет значение
подтверждённых фактов. Формулы и параметры не выводятся в интерфейсе.

## Какие рынки получает модель

Сборщик читает `ww-fast-bets-block-dsk`, отдельно от большой таблицы всех рынков.
Берутся настоящие карточки групп «Популярные на матч» и «Популярные на тайм»:
их названия, периоды, выбранные значения тотала/форы и все исходы. Ставки,
коэффициенты и переключатели линии не нажимаются. Значения не подбираются
по коэффициентам и не фиксируются в коде.

В наблюдении события `17124979` от 10.11.2026 это восемь карточек / 18 исходов:

| Период | Рынки |
| --- | --- |
| Основное время | Исход 1X2, фора, тотал, обе забьют |
| Первый тайм | Исход 1X2, фора, тотал, чёт/нечёт |

Источник может менять состав популярных карточек и значения линий. Правило
следует наблюдаемой разметке, а не этому перечню для всех будущих матчей.
Все наблюдаемые популярные карточки имеют приоритет над прежней эвристикой
`QWEN_MARKET_LIMIT`. Если пользователь явно выбрал другой рынок, он добавляется
к контексту. Без наблюдённых популярных блоков остаётся прежний отбор основных
рынков; он не объявляется чтением популярных блоков источника.

Связь популярного снимка с потоком проверяется по ID события, участникам,
виду спорта, времени начала и фазе. У популярного снимка своё время наблюдения.
Его обновление не делает старые цены общей таблицы свежими. Полная таблица
сохраняется в базе, а нейросети передаются отобранные условия без цен.

Рассчитываются все поддерживаемые исходы этих карточек. В кратком блоке
«Рынки» показаны до трёх вариантов с оценкой не ниже 55%; это не обещание выигрыша
и не оценка выгодности ставки. Для выгодности потребовалось бы сравнение с ценой,
которое здесь намеренно не выполняется.
Для сохранённых популярных условий вероятность может быть рассчитана и при
неподтверждённой доступности котировки; это отдельно отмечается в ограничениях.

## Данные и отсутствие порога в 30 матчей

Жёстких условий «30 матчей турнира», «пять игр команды» и минимальной суммы
весов больше нет. Один подтверждённый результат каждой команды уже может
использоваться. При отсутствии подробной истории используются наблюдаемые
сезонные показатели «За матч» с явными фильтрами «Общее» / «Хозяева / Гости».
Суммарные голы без знаменателя не принимаются за среднее число голов.

При наличии одновременно итогов и средних ориентировочный размер сезонной
выборки восстанавливается только при единственном согласованном целом числе
игр с допуском округления 0,0051. Это оценка размера, не подтверждённый список игр.
При неоднозначности используется слабый вес среднего без выдуманного числа матчей.
Показатели хозяев/гостей дополняют общий сезонный уровень с небольшим весом,
без двойного подсчёта одних и тех же игр.

Архив предоставляет до 1500 последних подходящих записей: матчи турнира и
матчи участников. Все переданные подтверждённые игры виджета также рассматриваются;
ограничение на 30 последних игр команды и годовой отсев убраны. Давность всё
равно уменьшает влияние результата. Результаты других турниров участников
получают половинный вес; класс каждого соперника отдельно не оценивается.

Виджет поддерживает время `time.uts`, `_dt.uts`, `start_at`, `date`; турнир
привязывается по названию либо `_utid`/`_tid`. Участник проверяется по ID;
`uid` сравнивается с `uid`, а не с `_id` другого пространства.
Будущие игры, текущая встреча, неподтверждённые участники, отмены, технические
результаты и неподходящие периоды не превращаются в завершённую историю.

Если финальный статус отсутствует, требуется единственный архивный результат
с теми же участниками, счётом и временем начала (до 120 секунд расхождения).
При сопоставлении используются записи, доступные на момент запроса.
Прошедшая дата и наличие счёта сами по себе не подтверждают завершённость.
Отсутствие такого подтверждения не запрещает отдельный расчёт по надёжным
сезонным средним, если они получены для обеих команд.

Если сведений для оценки обеих команд вообще нет, процент не выдумывается.
Live и другие виды спорта пока получают фактическую сводку без независимых процентов.

## Математическая модель

Для предматчевого футбола используется модель голов Пуассона с эмпирическим
байесовским сглаживанием Gamma–Poisson. Сначала оцениваются атака и защита команд.
При доступных сезонных средних они служат исходным уровнем; иначе исходный
уровень берётся из голов турнира. В отсутствие турнирной выборки используются
наблюдаемые сезонные средние, либо доступная подтверждённая история участников.

```text
w_i = 2^(-days_i / 90) × scope_weight_i
attack  = (α × attack_prior  + Σ w_i × goals_for_i)     / (α + Σ w_i)
defence = (α × defence_prior + Σ w_i × goals_against_i) / (α + Σ w_i)
```

`scope_weight` равен 1 для текущего турнира и 0,5 для другого турнира.
Без сезонного среднего `α = 6`, с ним — до шести условных матчей,
с учётом доступного ориентировочного размера выборки. Положительная слабая
регуляризация не позволяет маленькой нулевой выборке объявлять событие невозможным.

Пусть `μ` — среднее число голов одной команды в турнирной выборке, либо
исходный уровень по доступной статистике. При наличии турнирных результатов
оценивается поправка позиции хозяев `v = sqrt(μ_H / μ_A)`, иначе `v = 1`.

```text
λ_home = attack_home × defence_away / μ × v
λ_away = attack_away × defence_home / μ / v
P(H=h, A=a) = Poisson(h; λ_home) × Poisson(a; λ_away)
```

Суммы ячеек матрицы дают П1/Х/П2, двойной шанс, тоталы, обе забьют,
чёт/нечёт, индивидуальные тоталы, точный счёт и поддерживаемые форы.
Для целочисленных тоталов и фор вероятность возврата учитывается отдельно;
четвертные азиатские линии без однозначных правил не получают выдуманных оценок.

Оценка первого или второго тайма строится с половинными интенсивностями голов.
Это приближение равномерного темпа, а не наблюдённая история таймов.
Ограничение прямо указывается в отчёте. Корреляция голов, составы, травмы,
индивидуальный рейтинг соперников и отдельная поправка нейтрального поля
пока не моделируются. Малая или давняя выборка даёт предварительную оценку,
а не автоматический отказ в расчёте.

## Подробные аргументы Qwen

Карточка показывает полный расклад П1/Х/П2 и заметную отметку предварительной
оценки. Для каждого участника видны число подтверждённых матчей, диапазон дат
и использование сезонных средних; восстановленное по округлённым данным число
игр обозначается как приблизительное. Высокая вероятность не объявляется
доказанной частотой выигрышей. В рекомендациях не повторяется одна семья
рынков разных периодов. Коэффициенты и формулы в независимом отчёте отсутствуют.

Qwen должен дать общий сбалансированный аргумент и объяснение каждого
рекомендуемого рынка с подтверждёнными фактами и `market_keys`. Ссылки на
выдуманные рынки отвергаются. Объяснения выводятся у соответствующих рынков;
если объяснение не получено, это прямо указано. Сезонное среднее не объявляется
текущей формой без датированных последних результатов.

О проверке на завершённых матчах, защите от будущих данных и первом прогоне:
[winline-evaluation.md](winline-evaluation.md).

Qwen получает все доступные блоки статистики, выбранные рынки, историю,
расчётные оценки, ограничения и банк подтверждённых фактов с ID.
Новый ответ — `arguments: [{fact_ids, explanation, market_keys?}]`: один общий
аргумент и пояснение каждого выбранного рынка, до четырёх объяснений,
каждое обычно 120–300 символов, о значении показателей, доводах против исхода
и надёжности выборки. Вместо простого перечисления модель пишет, почему факт
важен для оценки атаки, защиты или характера ожидаемого матча.

Сервер вставляет точные факты и проценты сам. Объяснения не могут подменять
поле вероятности, придумывать ссылки, добавлять неподтверждённые числа,
обещать гарантированный выигрыш или раскрывать формулы. Неправильный ответ
получает одну небольшую попытку исправления; большой вход не отправляется повторно.
Проверка ссылок и чисел не доказывает правильность каждого смыслового вывода.
Для больших входов сохраняется обработка по частям с удалением повторных аргументов.

## Обновление и проверка

Кнопка разбора ставит в очередь только выбранный матч. Сборщик сначала обновляет
его страницу и популярные карточки, затем статистику участников. Пауза источника
соблюдается. Подготовка ограничена 240 секундами и не затрагивает службы нейросети.
Версия ключа кэша изменена; старые сохранённые отчёты не переписываются.

Нужны обновления приложения на VPS и сборщика `matchlab-statistics` на сервере
нейросети. Менять vLLM, Whisper, Kokoro, контекстное окно и GPU-настройки не нужно.

Тесты воспроизводят настоящую DOM-разметку популярных блоков, проверяют восемь
карточек / 18 исходов, направления фор, независимость от коэффициентов,
сезонный расчёт без архивных матчей, проверку фактов и длинные аргументы в интерфейсе.
На сохранённой статистике события `17124979` оценка всех восьми рынков получается
даже без архивной выборки; это проверка работоспособности, не проверка точности прогноза.

Точность нужно проверять по прогнозам, сохранённым до начала, и последующим
результатам: `python -m matchlab.chances_audit` считает Brier score, log loss
и калибровку. Пока достаточной проверки нет, это ограничение остаётся в отчёте.
