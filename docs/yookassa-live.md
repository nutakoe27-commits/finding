# Рабочий магазин ЮKassa

Пакеты: 1 разбор — 490 ₽, 5 — 2 190 ₽, 10 — 4 090 ₽. Разовые платежи; подписки с периодом 3 дня подключаются отдельно после одобрения ЮKassa,
см. [инструкцию](subscriptions.md). Владелец подтвердил рабочий магазин и собственную онлайн-кассу,
подключённую к ЮKassa. НДС не предъявляется (`vat_code=1`), УСН берётся из
настройки кассы; если настроено несколько СНО, явно укажите код 2 или 3.

## Подключение на VPS сайта

```bash
cd /root/matchlab
git pull --ff-only origin main
.venv/bin/python scripts/configure_yookassa.py --live
sudo systemctl restart matchlab.service
.venv/bin/python scripts/check_yookassa.py --site
```

Скрипт запрашивает Shop ID рабочего магазина и секретный ключ `live_` скрытым
вводом. Сначала проверяет магазин и подключение кассы через GET /me, затем
создаёт приватные копии `.env` и базы (для MySQL — проверенный SQLite export).
Ключ не выводится и не попадает в историю команд. Остальные настройки сохраняются.
При необходимости: `--tax-system-code 2` (УСН доходы) или `3` (доходы минус расходы).
Вариант УСН нельзя выбирать наугад. Без параметра используется СНО кассы.

Меняются только BILLING_ENABLED=true, BILLING_MODE=live,
BILLING_RECEIPTS_ENABLED=true, BILLING_PUBLIC_TESTING=false,
YOOKASSA_TAX_SYSTEM_CODE и реквизиты выбранного магазина. Новые поля/таблицы
добавляются при запуске приложения; прежние записи сохраняются.

В кабинете **рабочего** магазина включите уведомления:

`https://prognozich.online/api/billing/yookassa/webhook`

События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
Не требуется выключать проверку HTTPS. Уведомление само не подтверждает оплату:
сервер повторно получает объект из API ЮKassa с авторизацией рабочего магазина.

## Оплата и чеки

До оплаты покупатель указывает e-mail и принимает текущую оферту. Сервер сам
выбирает цену, количество и данные чека. Пакет оплачивается полностью, с чеком
`full_prepayment`, предмет расчёта `service`. В чеке количество равно числу
разборов; цена единицы — 490, 438 или 409 ₽ соответственно.

Успешный платёж должен иметь test=false, paid=true и точное совпадение магазина,
валюты, суммы, заказа и пользователя. Только после этого начисляются единицы.
Возврат браузера на сайт не начисляет баланс. Повторы и повторная проверка
сохраняют исходный заказ и Idempotence-Key.

При платном открытии единица списывается из самого раннего доступного пакета
(FIFO). Списание, привязка к пакету, открытие и задание для чека фиксируются
одной транзакцией. При повторном открытии нового списания или чека нет.
Бонусный доступ и бесплатная публичная история не расходуют предоплату.

Фоновая очередь сначала проверяет регистрацию чека предоплаты, затем отправляет
чек `full_payment` за предоставленный разбор с `settlements.type=prepayment`.
Нового денежного платежа это не создаёт. При временной ошибке задание повторяется
с тем же ключом; состояние хранится в БД и переживает перезапуск.
После истечения окна автоматического безопасного повтора неизвестного запроса
задание получает статус `review`: нужно проверить его в кабинете кассы/ЮKassa,
а не создавать новый чек вслепую.

В админке «Оплаты» по умолчанию выбран рабочий магазин. Видны суммы, возвраты,
состояния чеков; в заказе — оплаченные открытия и остаток по исходной цене пакета.
Если есть чеки со статусом «Требует внимания», проверьте кассу и первичный платёж.
Открытие оплаченного ответа не отменяется из-за задержки регистрации чека.

## Возвраты и переход с тестового магазина

Возвраты оформляются по запросу покупателя в кабинете ЮKassa по первоначальному
платежу с соответствующим чеком возврата. Для неиспользованного остатка берите
количество и цену из карточки заказа, а не текущий общий баланс аккаунта.
Пример: из 5 разборов за 2 190 ₽ использованы 2 — возврат 3 × 438 = 1 314 ₽.
Не удерживается комиссия и не пересчитывается цена уже использованных единиц.
Предоставленные услуги/претензии к качеству рассматриваются отдельно по оферте.
Webhook повторно подтверждает возврат через API и однократно корректирует баланс.

Тестовые платежи, деньги и ledger остаются отдельными (`mode=test`) и не
становятся реальной выручкой или купленными единицами. Уже открытые пользователем
ответы и бонусный остаток сохраняются. Проверочная история доступна только
отдельным выбором режима в админке; рабочий кабинет показывает рабочие покупки.

Фактическое прохождение денег и регистрацию чеков на вашем магазине можно
подтвердить только после ввода реквизитов на VPS и реальной покупки. Локальные
проверки используют фиктивный API и не списывают деньги.

Официальные контракты API: https://yookassa.ru/developers/api
и https://yookassa.ru/developers/using-api/webhooks .
