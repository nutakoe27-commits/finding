# Виды спорта Winline

Линия, хранилище и ИИ-разбор поддерживают обычные виды спорта, обнаруженные
в публичной навигации Winline. Футбол остаётся доступен. Добавлены хоккей,
теннис, баскетбол, настольный теннис, волейбол, единоборства, бейсбол, гандбол,
американский футбол, регби, футзал, пляжные виды, бадминтон, дартс, снукер,
водное поло, флорбол, гольф, кёрлинг, автоспорт и другие разделы.
Новые обычные разделы с незнакомым slug сохраняются с идентификатором и
наблюдаемым названием источника. Киберспорт и виртуальные игры отбрасываются.

Сборщик открывает фактические ссылки разделов и событий, не перебирает ID
и не конструирует URL несуществующих лиг. Корневые разделы получают приоритет
перед глубоким обходом турниров; очередь событий чередует виды спорта,
чтобы крупный футбольный раздел не забирал всё время первым.

## Рынки и правила

Каждый документ содержит `sport`, `sport_label`, `event_kind` и исходные
названия рынков, периодов и исходов. Несовпадение спорта с каноническим URL
отклоняется. Событие не может заменить ранее сохранённое событие другого спорта
с тем же ID. Старые футбольные документы остаются совместимы.

Карточка показывает явно распознанный рынок победителя и его период:
два исхода не превращаются в три. Основное время хоккея отличается от
победителя с ОТ/буллитами, сет — от матча, четверть — от игры. Если основной
рынок неоднозначен, карточка предлагает открыть все рынки вместо подстановки
коэффициентов из другого периода. Для большого рынка показываются первые
три исхода и полное число вариантов; на странице события доступны остальные.

События типа `outright` — гонки, соревнования и долгосрочные рынки — имеют
собственное название. Для них не создаются фиктивные хозяева и гости.

ИИ получает вид спорта и точный выбранный рынок. Он различает периоды,
основное время/ОТ, бой/раунд и гонку/квалификацию. Правила возврата и снятия
не выдумываются. Рыночные вероятности выводятся только из полного явно
распознанного рынка победителя; неполный набор вариантов не нормируется.
Объём контекста ограничен 12 рынками и 80 исходами, выбранный исход сохраняется.

Статистическая модель по историческим голам применяется **только к футболу,
предматчевому исходу АПЛ**. Хоккей, теннис и остальные виды используют разбор
сохранённых рынков; футбольные голы и вероятности на них не переносятся.

## Обновление

Сначала **на VPS**:

```bash
cd /root/matchlab
git pull --ff-only origin main
systemctl restart matchlab.service
```

Затем **на сервере сборщика**:

```bash
cd ~/matchlab-scraper-src
git pull --ff-only origin main
sudo systemctl stop matchlab-crawler.service
sudo bash scripts/install_market_crawler.sh --api-url http://127.0.0.1:18081 --sports all
```

Установщик обновляет только Matchlab. Новых Python-пакетов нет, существующие
ключ, браузерный кэш и SSH-туннель используются повторно. Перед сбором проверяется,
что приёмник на VPS поддерживает несколько видов спорта. Проверка доставки
одного полного снимка включает автосбор; это не подтверждение всего каталога.
Фактические события, количество и свежесть видны в интерфейсе после обхода.

По умолчанию `--sports all`. Для ограничения можно передать, например,
`--sports football,hockey,tennis,basketball`. Значение записывается в
`BOOKMAKER_SPORTS` в `/etc/matchlab-crawler.conf`.

Интервал между началами циклов остаётся 60 секунд без наложения. Полный обход
всех рынков всех видов спорта может занимать дольше; время наблюдения каждого
события не заменяется временем запуска процесса. Лимиты памяти 4 ГиБ,
двух CPU, четырёх вкладок, 5000 событий и 200 страниц списка сохраняются.
Достижение ограничений и ошибки делают отчёт частичным, а не полным успешным.

Проверка на сервере сборщика:

```bash
sudo journalctl -u matchlab-crawler -n 30 --no-pager
sudo cat /var/lib/matchlab-crawler/cycle-status.json
```

В отчёте `sports` содержит число сохранённых, полных и ошибочных документов
по видам спорта. В интерфейсе цифры в выборе спорта относятся к событиям,
доставленным в базу на VPS. Пустой сезонный раздел не заполняется примерными
матчами. При отличающейся разметке сайта нужны диагностика и адаптация парсера;
неподтверждённые страницы не объявляются полными.

## Проверки

Модульные проверки охватывают соответствие спорта URL, два/три исхода,
ОТ и периоды, события без пары соперников, разделение моделей и фильтров.
Браузер проверяет футбол, теннис, хоккей и гонки на ПК и телефоне, включая
выбор исхода и ИИ-запрос. Отдельный прогон использует настоящий Scrapy,
Chromium, DOM-парсер и защищённый HTTP-приёмник с локальными контрактными
страницами. Состояние транспорта в нём задано фикстурой; подключение и обрывы
WebSocket проверяются отдельно в `browser_capture_smoke.py`. Это проверки
программных контрактов, а не подтверждение текущей разметки всех живых разделов.
