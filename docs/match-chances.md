# Оценка вероятностей и короткий разбор

Кнопка ИИ-разбора сначала запрашивает статистику выбранного события. На VPS
формируется расчёт вероятностей. Нейросеть сопоставляет все сохранённые рынки,
статистику и историю по частям, затем пишет до трёх коротких аргументов.
Числа вероятностей и структура отчёта формируются сервером. Произвольные
проценты из ответа нейросети не используются. Параметры расчёта не передаются
в публичный контекст.

Каждое наблюдение нейросети содержит ID и точную цитату из полученного фрагмента.
Проверяются существование источника, наличие цитаты и числовые ссылки. Итоговые
аргументы ссылаются на эти наблюдения. Это не автоматическая гарантия правильности
смыслового вывода; исходные данные и ограничения сохраняются вместе с разбором.
Поиск и непроверенные записи не превращаются в подтверждённую историю.

Ответ содержит наиболее вероятный исход, до трёх оценённых рынков, аргументы и,
при наличии, ограничения. «Победные рынки» — название блока, а не обещание выигрыша.
Наиболее вероятный исход может иметь менее 50%, а ничья может оказаться вероятнее
победы любой команды. В интерфейсе исход и процент выделены отдельной карточкой;
оценка по котировкам имеет подпись «По линии». Рынки и аргументы показаны списками,
ограничения — раскрываемым блоком. Оформление действует и для сохранённых отчётов.

Независимая оценка в первой версии поддерживает предматчевый футбол. Требуются
достаточная история того же турнира, точная привязка участников и прошлые счета.
Оцениваются основной 1X2, двойной шанс, тоталы голов с однозначной линией,
обе забьют, точный счёт и некоторые половинные форы. Периоды, угловые,
карточки, четвертные линии и неизвестные правила не получают выдуманных оценок.
Счёт футбольного матча не используется как статистика тенниса или баскетбола.
Для live и недостаточной истории проценты по доступному однозначному рынку
помечаются «по линии»: это нормировка котировок, а не независимая оценка.

## Большой контекст

Прежний запрос на 139 рынков / 616 исходов занимал около 185 КБ и отклонялся ИИ.
Теперь все сохранённые поля разбиваются по JSON-путям. Длинные тексты сохраняют
смещения частей; рынки и исходы не удаляются ради уменьшения одного запроса.
Окно модели читается из `/v1/models`, счётчик токенов — из vLLM `/tokenize`.
Если эти возможности недоступны, используется консервативный предел по байтам.
После `context_limit` части разделяются повторно. Промежуточные наблюдения также
объединяются по частям, чтобы итоговый запрос не переполнился.

Одновременно выполняются не более двух вызовов. По умолчанию весь этап ИИ
ограничен 120 секундами и 256 попытками. Если обработать всё не удалось, ответ
помечается частичным либо расчётным, с причиной. Неполный разбор не выдаётся
за полный и не расходует бонусный разбор. В сохранённом контексте есть число
доставленных фрагментов и полностью обработанных рынков/исходов.

Необязательные настройки в `.env` на VPS:

```dotenv
# 0: определить по /v1/models; если сервер не сообщает окно, использовать 4096.
QWEN_CONTEXT_TOKENS=0
# Общее время этапа ИИ, включая разбиение и итог; допустимо 10–150 секунд.
QWEN_ANALYSIS_TIMEOUT_SECONDS=120
```

Не увеличивайте `QWEN_CONTEXT_TOKENS` сверх реального окна сервера модели.
Здесь не изменяются настройки vLLM и расход видеопамяти на загрузку модели.

## Диагностика

В админке отдельно видны: «ИИ ответил», «ИИ не вызывался», «ИИ · частично»,
«Превышен контекст», «Ошибка ИИ» и «Ответ из кэша», количество вызовов и частей.
Время в таблице — время запроса к сайту, включая поиск и подготовку, без отдельного
предварительного задания статистики. Кэш не выдаётся за новый вызов модели.
Для старых записей причина восстанавливается только при однозначной связи с
сохранённым разбором; иначе остаётся «Сводка · без диагностики».

На VPS, без вывода ключей:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab check-qwen
sudo journalctl -u matchlab.service --since '20 minutes ago' --no-pager | grep 'Qwen event'
```

При успехе видна строка `Qwen event complete: state=ready parts=N/N calls=K markets=139/139`.
Категории ошибок: `timeout`, `connection`, `proxy`, `context_limit`, `output_limit`,
`reasoning_only`, `authentication`, `model_or_endpoint`, `provider_http`, `invalid_response`.
Тексты запросов, ключи и цитаты источников в журнал не выводятся.

## Проверка качества

Проверка по действительно сохранённым до начала прогнозам, после поступления
завершённых результатов:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.chances_audit
```

Команда только читает базу, оценивает первый независимый прогноз каждого матча,
исключает повторные разборы и дубликаты пользователей. Выводит Brier score,
log loss и частоты реализации прогнозов в интервалах вероятности. При малой
выборке прямо отмечает это. Пока такой проверки на достаточном числе новых
матчей нет, оценка не называется откалиброванной; прибыльность не установлена.

## Обновление

Только на VPS сайта. Добавляется необязательное поле диагностики к существующей
таблице запросов; записи, пользователи и история сохраняются.

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.manage backup &&
git pull --ff-only origin main &&
sudo systemctl restart matchlab.service
```

Сборщик на сервере нейросети использует прежний протокол одноразовых заданий.
