# Оценка вероятностей и короткий разбор

Кнопка ИИ-разбора сначала запрашивает статистику выбранного события. На VPS
формируется расчётная оценка; нейросеть выбирает до трёх подтверждённых аргументов.
Числа и структура ответа формируются сервером. Произвольные проценты из ответа
нейросети не используются. Параметры расчёта не передаются в публичный контекст.

Ответ содержит победителя/наиболее вероятный исход, до трёх оценённых рынков,
аргументы и, при наличии, ограничения. «Победные рынки» — название блока, а не
обещание выигрыша. Наиболее вероятный исход может иметь менее 50%, а ничья
может оказаться вероятнее победы любой команды.

В интерфейсе исход и процент выделены отдельной карточкой; оценка по котировкам
имеет подпись «По линии». Рынки и аргументы показаны отдельными списками,
ограничения — раскрываемым блоком. Это оформление применяется также к ранее
сохранённым отчётам нового формата; прочие старые тексты сохраняют Markdown-разметку.

Независимая оценка в первой версии поддерживает предматчевый футбол. Требуются
достаточная история того же турнира, точная привязка участников и прошлые счета.
Оцениваются основной 1X2, двойной шанс, тоталы голов с однозначной линией,
обе забьют, точный счёт и некоторые половинные форы. Периоды, угловые,
карточки, четвертные линии и неизвестные правила не получают выдуманных оценок.
Счёт футбольного матча не используется как статистика тенниса или баскетбола.
Для live и недостаточной истории проценты по доступному однозначному рынку
помечаются «по линии»: это нормировка котировок, а не независимая оценка.

Все **сохранённые** рынки и исходы передаются в контекст нейросети, вместе с
подтверждённой статистикой. Это не обещает полного покрытия сайта. Если сервер
нейросети отклонит контекст, рынки молча не обрезаются: показывается расчётный
отчёт с ограничением. Сбой или некорректный ответ ИИ также не удаляет расчёт.

На VPS диагностика соединения (без вывода ключей):

```bash
cd /root/matchlab
.venv/bin/python -m matchlab check-qwen
sudo journalctl -u matchlab.service --since '20 minutes ago' --no-pager | rg 'Qwen event unavailable'
```

Без `rg` используйте `grep`. Категории: `timeout`, `connection`, `proxy`,
`context_limit`, `output_limit`, `reasoning_only`, `authentication`,
`model_or_endpoint`, `provider_http`, `invalid_response`.

Проверка качества по **действительно сохранённым до начала** прогнозам, после
поступления завершённых результатов:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.chances_audit
```

Команда только читает базу, оценивает первый независимый прогноз каждого матча,
исключает повторные разборы и дубликаты пользователей. Выводит Brier score,
log loss и частоты реализации прогнозов в интервалах вероятности. При малой
выборке прямо отмечает это. Пока такой проверки на достаточном числе новых
матчей нет, оценка не называется откалиброванной; прибыльность не установлена.

Обновление требуется только на VPS: `git pull --ff-only origin main` и
`sudo systemctl restart matchlab.service`. Сборщик на сервере нейросети
использует прежний протокол одноразовых заданий.
