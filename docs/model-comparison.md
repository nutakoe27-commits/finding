# Сравнение математических вариантов на фиксированной выборке

Команда `python -m matchlab.model_comparison` сравнивает кандидатов и сохраняет
JSON/CSV. Она не меняет производственную модель, не вызывает Qwen, не обращается
к букмекеру и не перезапускает службы. Используются numpy/scipy из обычных
зависимостей приложения. Все настройки фиксированы; по результатам проверяемых
матчей параметры не обучаются и не подбираются автоматически.

## Что есть в загруженном отчёте

Пользовательский `winline-statistics-100.json` содержит 40 выбранных матчей,
38 рассчитанных распределений и два пропуска. Это **не экспорт исходных
снимков**: сезонных показателей, полной истории и коэффициентов в нём нет.
Сравнение в рабочей среде использует именно этот файл, а не отдельный архив
результатов. SHA-256 входа записан в итоговом JSON.

Все основные кандидаты оцениваются на одних и тех же 38 играх. Пропущенные
исходной моделью игры не добавляются отдельным удобным кандидатам.
В общий рейтинг входят только методы, покрывающие всю эту когорту; прочие
сравниваются с исходной моделью и равномерным ориентиром на собственном
совпадающем подмножестве. Число матчей указывается в каждой строке.

## Варианты, доступные без серверной БД

1. **Пуассон v19** — сохранённый результат действующей независимой модели.
2. **Равномерный ориентир** — каждому исходу по трети. У него нет выбранного
   фаворита; доля угаданных фаворитов не выдумывается из порядка ключей.
3. **Смешивание с равномерным ориентиром** с долей 25% и 50%.
   Уменьшает уверенность, сохраняя порядок вероятностей. Это калибровочные
   преобразования, а не новое обучение командных рейтингов.
4. **Температурное сглаживание** `p_new ∝ p^(1/1.5)`.
5. **Поправка Диксона–Коулза** к малым счетам с фиксированным `ρ=-0.05` и
   `ρ=-0.10`. Это поправка к исходным интенсивностям, а не совместно обученная
   на истории полноценная модель Dixon–Coles. Если нужно, величина ρ
   ограничивается условием положительности всех четырёх поправок.
6. **Отрицательно-биномиальное распределение голов** с формой `k=5` и `k=10`.
   Средние сохраняются; дисперсия становится больше пуассоновской:
   `Var(G)=E(G)+E(G)^2/k`. Параметр k по проверяемым результатам не оценивается.

Для двух последних групп средние голов восстанавливаются численно из двух
независимых вероятностей сохранённого Пуассона. Обратное восстановление
проверяется по всем трём вероятностям с допуском `1e-7`. Неподходящее
распределение не выдаётся за Пуассон. Исходные значения атаки/защиты команд
при этом не известны и не переоцениваются. Изменяется форма распределения
при прежней оценке средних, а не весь механизм получения прогноза.

## Методы с серверной историей

С флагом `--with-server-data` доступны ещё два варианта.

- **Частоты турнира с prior Дирихле**: к числу каждого исхода прибавляется
  единица. Используются завершённые результаты текущего турнира, доступные
  к времени прогноза. Без таких результатов это ровно равномерный prior;
  размер истории виден в отчёте.
- **Elo–Davidson**: рейтинги обновляются последовательно, старт 1500,
  `K=20`, поправка хозяев 50 пунктов. История ограничена текущим турниром.
  Davidson отдельно учитывает ничью, её prior берётся из сглаженных частот
  того же турнира. Неизвестный участник даёт пропуск, не выдуманный рейтинг.

Архив читается через те же ограничения времени наблюдения и получения,
что и в независимой модели. Результат целевой игры в обучение не попадает.
Если последняя версия результата обновлена после времени прогноза, она
исключается; старые версии из журнала автоматически не восстанавливаются.
Поэтому повторный запуск на изменившейся серверной БД может иметь меньше
доступной истории, чем исходная реконструкция.

## Шин и конвертация коэффициентов

Это **рыночные ориентиры**, а не независимая модель силы команд.
Необходимы три десятичных коэффициента П1/Х/П2 за основное время из одного
исторического снимка. Пусть `q_i=1/odds_i`, `Q=Σq_i`.

- Пропорциональный вариант: `p_i=q_i/Q`.
- Степенной вариант: `p_i=q_i^k`, где k решает `Σq_i^k=1`.
- Метод Шина:
  `p_i=(sqrt(z^2+4(1-z)q_i^2/Q)-z)/(2(1-z))`, где z решает `Σp_i=1`.
  В коде используется численно устойчивая эквивалентная форма.
  Для отрицательной маржи решение с z в `[0,1]` не придумывается:
  Шин помечается недоступным, остальные способы могут быть рассчитаны.

Поиск идёт по `bookmaker_quotes`, неизменяемым контекстам `event_analyses`
и сохранившимся предматчевым книгам `bookmaker_event_markets`. Учитываются
участники, турнир, время начала, источник Winline, открытые исходы и полное
условие основного времени. Для текущей сохранённой книги проверяется время
всего захвата, а не только более ранняя дата отдельного рынка.
Рыночный снимок должен быть не позже `forecast_at` и до начала игры.
Разные события/цены при неоднозначной привязке исключаются.

Цены после прогноза, сегодняшний рынок и коэффициенты `1/p`, искусственно
полученные из собственной модели, не заменяют историческую линию.
Если нужных цен нет, результат Шина — `unavailable`, не придуманная метрика.
В `market_models` есть парные результаты исходной модели на **тех же матчах**.

## Запуск

Локально, без серверной БД:

```bash
.venv/bin/python -m matchlab.model_comparison \
  --report winline-statistics-100.json \
  --output data/evaluations/model-comparison.json
```

На VPS сайта с ранее созданным отчётом:

```bash
cd /root/matchlab
git pull --ff-only origin main
.venv/bin/python -m matchlab.model_comparison \
  --report data/evaluations/winline-statistics-100.json \
  --with-server-data \
  --output data/evaluations/model-comparison.json
```

База берётся из `Settings.from_env().database` и открывается в `mode=ro`.
Можно вместо флага явно указать `--database /путь/к/matchlab.sqlite3`.
В результат не копируются пользователи, заметки, токены или содержимое .env.

## Интерпретация

Brier и log loss оценивают всё распределение П1/Х/П2; меньше — лучше.
Попадания фаворита не проверяют правильность процентов. Близкие метрики
на 38 играх не доказывают превосходство. Выбор лучшего кандидата по этой же
выборке — исследовательский выбор; затем нужны новые независимые матчи,
на которых настройки больше не меняются.

[Результат на пользовательском отчёте](../evaluation_results/model-comparison/2026-11-10/README.md):
ни один из доступных без БД кандидатов не обошёл равномерный ориентир по
обеим вероятностным метрикам. Производственная модель автоматически
не переключается на выбранную строку.
