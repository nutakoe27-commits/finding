# Линия матчей и разбор с ИИ

Основной сценарий: **матч → рынок или исход → «Получить разбор ИИ»**.
Внешний вид следует структуре букмекерской линии; оформления ставок в сервисе нет.
На широком экране турниры находятся слева, матчи — в центре, панель разбора —
справа. На телефоне панель расположена внутри страницы выбранного матча.
Производитель модели в интерфейсе и пользовательских ошибках не показывается.

На главном экране оставлены поиск, турниры, дата, предстоящие/live/все наблюдения,
коэффициенты основного исхода, число рынков и свежесть снимка. Фильтры применяются
на сервере до пагинации, поэтому поиск охватывает весь сохранённый каталог.
Прежние снимки сразу показывают коэффициенты без повторного сбора всей линии.
Неполные и устаревшие данные помечаются отдельно; live — фаза в снимке,
а не подтверждение текущего счёта и минуты.

Кнопка звезды сохраняет ID матча в текущем браузере, до 100 встреч. Аккаунты
для этого не создаются. Группы рынков раскрываются по необходимости; названия,
таймы, параметры и коэффициенты поступают из сохранённого документа.

ИИ получает конкретный снимок, выбранный рынок/исход и необязательные заметки.
Контекст ограничен 12 рынками и 80 исходами; выбранный исход включается всегда.
В ответе показано, сколько сохранённых рынков было передано. Рыночные вероятности
из коэффициентов нормируются по марже и явно отличаются от независимой модели.
Для поддерживаемого предматчевого события АПЛ дополнительно передаётся расчёт
по историческим голам с периодом обучения. Составы, травмы, новости и текущий
счёт автоматически не подключаются. Заметки считаются непроверенными данными.

Ответ сохраняется вместе с временем и точным контекстом запроса. История показывает
20 последних разборов. Повтор идентичного запроса по тому же снимку использует
сохранённый ответ до 10 минут; переход снимка в устаревший статус или наступление
времени матча меняет ключ повтора. При обновлении снимка во время разбора ответ
остаётся привязан к прежнему наблюдению, что указано рядом с ним. Старый ответ
не переносится на другой матч при переключении страниц.

Ручной расчёт, результаты исторической проверки и источники данных доступны
через «Состояние сервиса». Основной сборщик и формат доставки рынков не меняются.

## Обновление существующей установки

Только на VPS:

```bash
cd /root/matchlab
git pull --ff-only origin main
systemctl restart matchlab.service
```

Новых пакетов Python нет. Таблица истории разборов и индекс поиска снимков
создаются автоматически. Существующие матчи, прогнозы, коэффициенты и ключи
сохраняются. Сервер сборщика, сервер ИИ и SSH-туннели обновлять не нужно.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/bookmakers/events` | Каталог: `search`, `competition`, `phase=upcoming/live`, `day=YYYY-MM-DD`, `ids`, `sort=kickoff/freshness`, `limit`, `offset` |
| GET | `/api/bookmakers/events/ID/markets` | Рынки и исходы выбранной встречи |
| GET | `/api/bookmakers/events/ID/analysis` | Доступность отдельной статистической модели |
| POST | `/api/bookmakers/events/ID/explain` | Разбор снимка: необязательные `market_key`, `outcome_key`, `observed_at`, `notes` |
| GET | `/api/analyses` | Последние 20 ответов без полного контекста |
| GET | `/api/analyses/ID` | Ответ и точный контекст сохранённого разбора |

`observed_at` предотвращает незаметный разбор другого снимка, если данные
изменились между выбором исхода и запросом. Недоступный или исчезнувший исход
не отправляется ИИ. Одновременные новые разборы ограничены одним запросом;
повторный ответ из истории доступен без обращения к модели.
