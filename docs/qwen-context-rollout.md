# Qwen 128K: один контролируемый тест и откат

На сервере работают 1Cat-vLLM на двух V100 32 ГБ, Kokoro и Whisper на GPU 0.
Успешно проверенный профиль Qwen: окно 32768, gpu-memory-utilization=0.82,
max-num-seqs=4 и max-num-batched-tokens=8192.

## Что установлено диагностикой

- 128K / 0.82: CUDA OOM при инициализации. Дополнительное выделение 848 МиБ
  не поместилось при примерно 833 МиБ свободной памяти GPU 0.
- 128K / 0.70: сервер дошёл до первого запроса из 19 входных токенов, затем
  упал в `recompute_w_u_fwd -> Triton autotuner -> do_bench` операции Gated DeltaNet.
- `/models` и `/tokenize` продолжали отвечать после `EngineDeadError`.
  Сообщение окна 131072 не подтверждает исправность генерации.
- API вернул HTTP 200 при ошибке ядра. Клиент распознаёт объект ошибки
  и не считает его результатом Chat Completions; диагностика нагрузки
  останавливается перед следующим запросом при неправильной структуре ответа.

Установленный tokenizer отдельно задан как `QuantTrio/Qwen3.6-27B-AWQ`,
модель — `mattbucci/Qwen3.8-27B-AWQ`, API-алиас —
`QuantTrio/Qwen3.5-35B-A3B-AWQ`. Совместимость токенизатора требует отдельной
проверки; этот параметр не меняется одновременно с исправлением OOM.

## Проверочный профиль

Это экспериментальный профиль, а не подтверждённая рабочая конфигурация.
Изменение требует перезапуска общей vllm.service. Текущие запросы Qwen обоих
проектов прервутся до загрузки модели. Whisper и Kokoro остаются работать.

На сервере нейросети сохраните копию и откройте текущий запуск:

```bash
cd /home/user/1Cat-vLLM &&
qwen_trial_dir="$(sudo mktemp -d /var/tmp/vllm-final128k.XXXXXX)" &&
sudo cp -a start_vllm38.sh "$qwen_trial_dir/original.sh" &&
printf 'Копия текущего файла: %s\n' "$qwen_trial_dir/original.sh" &&
sudo nano start_vllm38.sh
```

В существующей команде поменяйте значения, не дублируя флаги:

```text
--max-model-len 131072 \
--gpu-memory-utilization 0.60 \
--max-num-batched-tokens 2048 \
--max-num-seqs 2 \
--enable-chunked-prefill \
--enforce-eager \
```

Сохраните остальные аргументы и правильные продолжения строк. Если последний
аргумент завершает команду, у него не должно быть лишнего `\`.
`--enforce-eager` отключает CUDA Graphs / torch.compile, но не Triton-ядра
и их autotuning. Меньший бюджет, prefill и число слотов дают больше запаса
для временных буферов. Скорость и параллельная ёмкость могут уменьшиться.
Точный допустимый размер контекста подтверждается настоящим запросом.

Не добавляйте одновременно ручной `--kv-cache-memory-bytes`: он переопределяет
автоматическое определение размера кэша через gpu-memory-utilization.
В этом тесте не устанавливайте новые пакеты и не редактируйте Triton / 1Cat.

```bash
sudo bash -n /home/user/1Cat-vLLM/start_vllm38.sh &&
sudo systemctl reset-failed vllm.service &&
sudo systemctl restart vllm.service
```

Смотрите только новые сообщения (Ctrl+C завершает просмотр, а не службу):

```bash
sudo tail -n 0 -F /var/log/vllm.log
```

После `Application startup complete` выполните на VPS один короткий тест:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab check-qwen
```

Успех — `chat_completions: ok`. При OOM, EngineDeadError, повторных падениях
или отсутствии рабочего короткого ответа не запускайте большой контекст.
Верните рабочий профиль ниже, сохранив лог для дальнейшего изучения.

## Рабочий откат 32K

Сохранённая выше копия отражает файл перед последним тестом и могла содержать
уже неработающий профиль 128K / 0.70. Она не считается проверенным откатом.

В `start_vllm38.sh` верните:

```text
--max-model-len 32768 \
--gpu-memory-utilization 0.82 \
--max-num-batched-tokens 8192 \
--max-num-seqs 4 \
```

Удалите добавленный в эксперименте `--enforce-eager`. Chunked prefill
можно оставить явно включённым: в рабочем профиле он уже был включён.
Проверьте синтаксис и перезапустите только vllm.service теми же командами.
Затем подтвердите короткий Chat Completions на VPS.

## Matchlab после успешного теста модели

После короткого ответа проверьте `inspect-qwen-context`. Окно 131072 вмещает
сохранённый запрос из 100784 входных токенов с резервом, но не доказывает,
что его инференс укладывается в ресурсы и время.

Размер одной входной части на VPS регулируется отдельно:

```dotenv
QWEN_CONTEXT_TOKENS=0
QWEN_BATCH_TOKENS=120000
QWEN_PARALLELISM=1
```

После изменения `.env` нужен перезапуск только matchlab.service.
Проверяйте один настоящий разбор с наблюдением за очередью обоих проектов.
Не утверждайте готовность 128K до успешного выполнения реального запроса.

Для чтения структуры systemd-запуска без ключей доступен
`scripts/configure_qwen_context.py inspect --unit vllm.service`.
Старый `prepare --tokens 131072` меняет лишь число окна и не делает данный
проверочный профиль: повторять с ним уже падавший запуск не следует.
