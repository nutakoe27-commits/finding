# Вердикт ИИ: «Заходим / Не заходим»

С 13.11.2026 пользовательские действия называются «Заходим / Не заходим»,
итоги — «Зашло / Не зашло». Показ размеров денежных вложений и виртуального
баланса убран. Параметры `stake_*`, `paper_*` и расчёты старых экспериментов ниже
сохранены как внутренний исторический протокол; в пользовательский разбор они
не выводятся. Данные и решения прошлых разборов не переписываются.


Экспериментальный режим `EVENT_ANALYSIS_MODE=neural-verdict` заменяет расчётный
разбор матча качественным решением Qwen. Первый вариант поддерживает только
предматчевый футбол и победу команды за основное время: П1 или П2. При сомнениях
ИИ может пропустить матч. Ничья учитывается как риск выбранной ставки, но сама
не предлагается. Для live и остальных видов спорта этот режим выдаёт пропуск.

Независимая модель, Пуассон, Elo, Shin, нормировка коэффициентов, рассчитанные
вероятности, value и математический подбор доли банка в этом пути не вызываются.
Старый режим `independent` сохранён для сравнения и отката.

## Что получает Qwen

- Названия команд, турнир, время начала и время наблюдения.
- Исходные коэффициенты полного рынка П1/Х/П2, без преобразования в вероятности.
- Сезонные показатели забитых и пропущенных мячей с разделением средних,
  итогов и домашних/гостевых значений.
- До восьми последних подтверждённых результатов каждого участника, известных
  на момент входа. Встречи текущего турнира имеют приоритет и передаются отдельно
  от матчей других турниров или с неподтверждённым турниром.
  В каждой строке подписан исход именно для этого участника, включая игры в гостях.
  `history_order=newest_first` и `outcomes` задают порядок и исходы, а последние
  известные результаты выделяются в начале текста. Это показанная история,
  которая может быть неполной, а не утверждение о всех матчах календаря.
- Проверенные строки таблицы для конкретных участников. Неоднозначные строки
  и данные игроков без подтверждённой принадлежности командам не используются.
- Ограничения данных; заметка пользователя передаётся как непроверенная заметка.

Вместо всего архива и повторяющихся технических структур передаётся компактный
список фактов с идентификаторами. Лимит списка — 11 КБ; сокращение отмечается.
Текст целевого результата, прежние прогнозы и параметры математической модели
в запрос не попадают. Интернет-поиск не вызывается.

Ссылки на факты проверяются сервером. Число в объяснении должно присутствовать
в цитируемом факте. Выбор команды требует как минимум двух разных фактов
статистики/истории. Факт сопоставления может ссылаться на обе исходные записи;
он не создаёт дополнительных независимых наблюдений. Это проверка опоры на вход, а не доказательство правильности
интерпретации: качество аргументов Qwen нужно оценивать отдельно.

У каждого факта указаны участник и область данных. Строка таблицы связывается
с командой по точному нормализованному имени. Другое имя допустимо только как
алиас из структурированного виджета с тем же ID матча и разными ID двух команд.
Частичное совпадение и предположение о прозвище не используются. Проверяется
знакомый набор футбольных колонок; неизвестные колонки, противоречивые и дублирующие
строки исключаются. Фильтры таблицы без подтверждения явно отмечаются.
Обрезка факта при упаковке отмечается в нём и в ограничениях; сырой снимок
статистики при этом остаётся сохранённым. Это относится только к новому режиму.

## Ответ и размер ставки

Протокол `neural-verdict-v6.2` разделяет **предпочтительную команду** и **решение
о ставке**. Например, предпочтение хозяев совместимо с решением пропустить матч.
Если выбрать сторону нельзя, предпочтение равно `null`; ставка при этом невозможна.
Карточка показывает оба вывода отдельно, затем сравнение хозяев и гостей,
сильнейший встречный довод, роль исходных коэффициентов и конкретную причину действия.
При ставке добавляется лимит риска. Вероятностей и
процентов уверенности в ней нет. Процент в строке лимита относится только к
отдельному игровому банку, который пользователь допускает потерять.

Каждая сторона сравнения обязана ссылаться на собственные факты статистики/истории;
объяснение линии — на факт с котировками. Причина пропуска выбирается из конфликта
фактов, недостатка данных, довода о ничьей, сомнения в цене или отсутствия предпочтения.
Для конфликта/ничьей/отсутствия предпочтения требуются ссылки на обе стороны,
для сомнения в цене — на котировки. Общее слово «нестабильность» и отсутствие
гарантии в инструкции не считаются достаточным объяснением. Проверка структуры
и ссылок не заменяет проверку смысла текста и не гарантирует качество прогноза.

В v5 встречный довод направлен против выбранного предпочтения: слабость этой
команды, сила соперника или подтверждённый довод о ничьей. Слабость соперника
сама по себе не становится доводом против выбранной команды. Название блока
в интерфейсе явно указывает, чьей победе может помешать описанный фактор.
При отсутствии предпочтения блок объясняет, что мешает выбрать сторону.

Домашняя/гостевая забиваемость и пропускаемость сопоставляются с общими средними
отдельно. `venue_vs_overall` и текст факта описывают только «меньше / больше /
столько же» для каждого исходного показателя. Меньшее число пропущенных нельзя
обобщать как ухудшение вместе с меньшей забиваемостью. Это сравнение наблюдений
при разных фильтрах, без поправки на состав соперников и без расчёта шансов.
Для факта с котировками и ограничений зарезервирована часть лимита контекста.

В v6 добавлены факты `kind=comparison` с `source_fact_ids`. Сопоставляются общие
средние с общими, а домашние/гостевые — в отдельном фильтре. Для недавних результатов
берётся одинаковое число последних сохранённых встреч текущего турнира, до трёх
с каждой стороны. Одинаковый набор исходов не объявляется преимуществом в форме.
Даты выборок могут различаться, полнота календаря не предполагается. В истории
отдельно подписана разница мячей именно для участника. Это описательная проверка
исходных данных, без прогнозной модели и расчёта вероятностей.

Сервер отклоняет некоторые однозначно распознаваемые противоречия: перевёрнутое
«больше/меньше» с определёнными командой, показателем и фильтром; лучшую недавнюю
форму на основании одинаковой сводки исходов; «крупное поражение» при разнице
меньше трёх мячей; невозможность выбрать сторону при уже выбранном предпочтении;
утверждения об известных причинах назначения цены букмекером. Для неоднозначного
сравнения без определённого фильтра вывод не угадывается. Проверки не понимают
произвольную прозу целиком и не доказывают корректность остальных рассуждений.
Схема ответа из v4 сохранена. Реальные ответы по-прежнему требуют оценки.

Если число есть во входе, но отсутствует среди процитированных источников,
возвращается ошибка ссылки `verdict_fact_reference`, а диагностика
`numbers_elsewhere_in_input` показывает возможные ID для исправления. Сервер не
добавляет ссылки автоматически: модель должна сослаться на подходящий источник
или убрать неподтверждённое утверждение. Число, которого нет во всём входе,
остаётся ошибкой `unsupported_number`. В v6.2 допускается до трёх последовательных
попыток: исходный ответ, исправление с диагностикой и новый ответ из исходных
фактов. Перед третьей попыткой неверный ответ не копируется в диалог. Дополнительного
отдельного вызова ИИ для проверки смысла нет. Ошибки соединения, авторизации,
таймаут и превышение входного окна не запускают повторные вызовы.

В v6.1 отрицание «не является гарантией результата» принимается как оговорка,
а обещания выигрыша по-прежнему отклоняются. Явные ссылки вида `(F7)` или
`(F6, F7)` в тексте переносятся в `fact_ids` и удаляются из отображаемой прозы.
Это исправление формата явно указанных ID, без подбора источника по числу или
содержанию утверждения. Неизвестные ID, превышение лимита ссылок, неподтверждённые
числа и смысловые противоречия остаются ошибками. Исправления формата отмечаются
в `format_normalizations` и диагностике попытки; нового запроса к Qwen ради
таких исправлений не требуется. Предпочтение и решение модели не меняются.

Если все попытки отклонены или данных недостаточно, итог явно показывает
**«Претендент: Никто. Решение: Пропустить матч»** с причиной. Для администратора
сохраняется различие между ошибкой ИИ, отсутствием входа и осознанным пропуском
модели. Все выполненные вызовы входят в учёт токенов.

Live остаётся в каталоге со счётом и рынками. Нынешний режим вердикта не делает
лайв-прогноз: он возвращает явный пропуск с причиной `live_not_supported`, без
запроса обновления статистики и без вызова модели. Для завершённого события,
другого вида спорта и неподтверждённой стадии также показывается конкретная причина.

ИИ выбирает категорию `small` или `standard`. Сервер переводит её в фиксированный
потолок: по умолчанию **0,25% или 0,5%** исходного игрового банка на ставку.
`VERDICT_MAX_STAKE_PCT` задаёт верхнюю категорию в пределах 0,01–0,5; нижняя —
её половина. Произвольный процент из текста модели не принимается. Это условие
эксперимента, а не найденный оптимальный размер ставки. Безрисковых ставок нет;
ограничение одной ставки также не ограничивает суммарный риск многих ставок.

При отсутствии свежих коэффициентов, подробной статистики, подтверждённых фактов
по обеим командам или предматчевой стадии сервер сразу выдаёт пропуск **без вызова Qwen**.
Причины показываются в карточке. Это вынужденный пропуск, а не решение нейросети.
Котировки действуют для
решения не дольше 180 секунд. Если за время генерации они устарели или начался
матч, рекомендация отменяется; устаревшая рекомендация не возвращается из кэша.

Один вызов ограничен 90 секундами и 1200 выходными токенами; thinking отключается
только для этих запросов. При некорректном JSON/ссылках на факты возможен один
повтор: модель получает предыдущий ответ и конкретное замечание проверки.
Для неподтверждённых чисел в закрытой диагностике сохраняются номер аргумента,
его ссылки на факты и сами неподтверждённые числа; полный ответ не пишется в журнал.
Таймаут или ошибка соединения автоматически не повторяются. Ошибка
модели отображается как защитный пропуск, отдельно от осознанного решения ИИ.
Службы и конфигурация сервера vLLM не меняются.

В v4 пример ссылок строится из фактических ID каждого входа: фиксированного
несуществующего ID в инструкции нет. Регистр, пробелы и простой список ссылок
нормализуются; разрешены до восьми существующих ID на блок. Неизвестные ID,
ссылки на чужую сторону и неподтверждённые числа по-прежнему отклоняются.
Проверка возвращает поле и конкретное правило, собирая ошибки всех доступных
блоков для одного исправления. Предупреждение «не гарантирует победу» допускается;
обещание гарантированного выигрыша и численная уверенность запрещены.

Файл отладочного теста сохраняет отклонённые ответы (не более 8000 символов каждый,
с отметкой обрезки и SHA-256) в `generation.attempts[].rejected_response`.
Он создаётся атомарно с правами 600 ещё до записи содержимого. В production
полный отклонённый ответ в диагностику анализа не добавляется; в журнале службы
пишутся только категория ошибки и имя поля.

## Выкат на VPS сайта

```bash
cd /root/matchlab &&
git pull --ff-only origin main &&
.venv/bin/python scripts/configure_neural_verdict.py &&
sudo systemctl restart matchlab.service
```

Скрипт изменяет только `EVENT_ANALYSIS_MODE` и `VERDICT_MAX_STAKE_PCT` в `.env`.
Резервная копия сохраняется в `.local/verdict-config-backups/` с правами 600.
Адрес API, имя модели, ключи и другие настройки сохраняются. Перезапускается
только приложение сайта. На сервере нейросети команд нет: используется прежний API.

Логи новых запросов:

```bash
sudo journalctl -u matchlab.service -f -o cat |
  grep --line-buffered -E 'Analysis job|Qwen event.*neural-verdict|Qwen completion|Qwen verdict'
```

Откат режима без изменения модели:

```bash
cd /root/matchlab &&
.venv/bin/python scripts/configure_neural_verdict.py --mode independent &&
sudo systemctl restart matchlab.service
```

## Десять случайных матчей на сохранённых снимках

Настоящая проверка выполняется **на VPS с базой сервиса**. Выгруженный отчёт
прежних математических моделей не содержит полного исторического входа и не
заменяет эту базу. Команда читает её без записи и вызывает настроенный Qwen:

```bash
cd /root/matchlab &&
.venv/bin/python -m matchlab.verdict_trial --limit 10 \
  --exclude-report data/evaluations/neural-verdict-10-v2.json \
  --output data/evaluations/neural-verdict-10-v5.json
```

Порядок проверки:

1. Найти завершённые футбольные матчи с однозначной привязкой записанной **до
   начала** статистики. Для каждой встречи оставить самый ранний пригодный снимок.
2. Во всей базе проверить совместную доступность статистики и исторических
   коэффициентов. Время входа — первый момент, когда оба уже были доступны,
   статистика не старше часа, котировки не старше 180 секунд, а матч ещё не начался.
   Коэффициент, записанный после статистики, можно использовать с **более поздним**
   временем входа; перемещать его назад во времени нельзя. Live-данные не подходят.
3. Исключить входы, которые заранее требуют пропуска. Из остальных случайно выбрать
   до десяти, сохранить seed и входы с хешами **до первого вызова**. Отбор зависит
   только от доступности данных, а не от результата встречи, величины коэффициента
   или будущего вердикта ИИ. Если пригодных четыре — тестируются четыре, без
   дополнения шестью вынужденными пропусками. Если ни одного — сохраняется
   `state=no_eligible_inputs`, запросов к Qwen нет.
   При `--exclude-report` просмотренные встречи из указанного старого отчёта также
   исключаются **до** случайного выбора; можно передать несколько отчётов.
4. Отправлять независимые запросы по одному, без ответов на другие матчи и без
   результата проверяемой встречи. Считать задержку ответа частью исторического
   сценария: если за неё истёк срок котировок/начался матч, тоже пропуск.
5. После каждого вызова сопоставить выбранную команду с итогом. Ничья — проигрыш
   П1/П2. Сохранить объяснение, диагностику, исход и виртуальный результат.

В `source_inventory` выводятся `eligible_statistics`, число сохранённых котировок
`historical_price_snapshots`, число совместно пригодных входов `eligible_verdict_inputs`
и причины исключения `excluded_joint_inputs`. Основные причины: нет котировок
этой встречи; они стали доступны только после начала; к моменту их получения
статистика уже устарела; нет совместного свежего наблюдения.
`inputs_with_fresh_prices` и `inputs_requiring_skip` описывают выбранную выборку.

Это выборка матчей с достаточно полными записанными данными. Нельзя переносить
её точность на весь каталог или сравнивать с прежними моделями без одинаковых
матчей и времён входа. Итоги старого теста, где все десять входов заранее требовали
пропуска, не характеризуют способность Qwen выбирать победителя.

Размер виртуального банка — 100 единиц. Ставка равна фиксированной доле **исходных**
100 единиц, без увеличения после выигрышей или проигрышей. Никакие реальные ставки
не совершаются. Метрики отдельно показывают число рекомендаций, пропусков,
попадания **среди ставок**, покрытие выборки и виртуальный финансовый результат.
Нулевые рекомендации дают неопределённую точность (`null`), а не 100% успеха.

Отдельно считаются `preference_evaluated`, `preference_hits`, `preference_accuracy`,
`preference_coverage` и `preference_without_bet`. Предпочтение проверяется даже при
осознанном пропуске ставки. Ничья означает, что П1/П2 не угадано. Отсутствие
предпочтения, ошибка модели и ответ после начала матча не считаются попаданием.
Истечение срока котировки отменяет ставку, но не мешает проверке предпочтения,
если ответ ещё предматчевый. Эти метрики относятся к тесту, а не к вероятностям,
передаваемым модели или показываемым в карточке.

Для новой оценки используйте встречи, результаты которых ещё не разбирали.
В примере выше исключены четыре матча из отчёта v2. Если они были единственными
пригодными в базе, новый тест вернёт ноль: нужно накопить другие предматчевые
снимки и дождаться результатов. Повтор на тех же четырёх без `--exclude-report`
может служить отладкой формата, но не независимой оценкой улучшения.

Перед каждым вызовом проверяется очередь ИИ сайта. При занятой очереди тест
сохраняется со статусом `paused_site_busy`, без остановки служб. Другие приложения
с тем же Qwen не видны в этой очереди; последовательный тест всё равно создаёт
нагрузку на общий сервер. Возобновление использует ту же выборку и не повторяет
уже завершённые вызовы:

```bash
.venv/bin/python -m matchlab.verdict_trial --resume \
  --output data/evaluations/neural-verdict-10-v5.json
```

Для предварительной проверки доступности данных без генерации добавьте
`--prepare-only`; затем продолжите через `--resume`. `--seed 42` позволяет
воспроизвести случайную выборку из неизменившейся базы. Существующий файл не
перезаписывается без `--resume`; для другого эксперимента нужен другой `--output`.
Одновременный запуск на один файл блокируется.
Планы предыдущего протокола не возобновляются новым кодом: сохраните старый JSON
и используйте отдельный файл `neural-verdict-10-v5.json`, чтобы не смешать эксперименты.
`--exclude-report` применяется при подготовке, а при `--resume` уже нельзя менять выборку.

Для диагностики формата начните с одного известного события, например:

```bash
.venv/bin/python -m matchlab.verdict_trial --limit 1 --event-id 17068499 \
  --output data/evaluations/neural-verdict-debug-v5-one.json
```

Такой прогон явно помечается `diagnostic_only=true`, `selection_policy=targeted-debug-input-v1`.
Это отладка на уже известной встрече, а не случайный тест качества. Он читает только
сохранённые предматчевые данные выбранного события; результат встречи в запрос к
модели не попадает. При отказе локальный JSON содержит сам отклонённый текст и
точные замечания, позволяя разбирать проблему без повторной генерации.

JSON содержит сами входы и ответы: храните его локально, не публикуйте базу или
пользовательские данные. Файлы стандартного имени исключены из Git. Сводку можно
отправить для разбора; результат десяти матчей не подтверждает преимущество
стратегии. Если большая часть пропущена из-за отсутствия исторических коэффициентов,
это проверка доступности данных, а не достаточный тест способности ИИ выбирать ставки.

Автоматические тесты проверяют протокол, слепой вход и интерфейс на локальных
фиксированных ответах. Они не являются результатами настоящего Qwen на матчах.
