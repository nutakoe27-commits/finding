# Подписки с периодом 3 дня и расход разборов

Таблица ниже описывает исходные тарифы до первой публикации через редактор.
Текущий каталог, скидки и документы меняются в **Админка → Тарифы и скидки**:
[инструкция редактора](pricing-editor.md). Уже оформленные договоры сохраняют
согласованные условия независимо от нового каталога.

## Что продаётся

| Подписка | Каждый успешный платёж | Списание денег |
| --- | --- | --- |
| 3 разбора / 3 дня | +3 на постоянный баланс | 490 ₽ раз в 3 дня (каждые 72 часа) |
| 15 разборов / 3 дня | +15 на постоянный баланс | 2 290 ₽ раз в 3 дня (каждые 72 часа) |
| Безлимит / 3 дня | безлимитный доступ на 72 часа | 6 090 ₽ раз в 3 дня (каждые 72 часа) |

**Разбор расходуется ТОЛЬКО при открытии нового сохранённого решения «Заходим».**
Полный ответ «Не заходим» с претендентом и аргументами бесплатен. Подготовка,
ошибки, отсутствие данных и повторный просмотр не расходуют единицы. Это правило
относится и к разовым пакетам, и к бонусам. Открытие требует явного действия;
получение ответа от ИИ само по себе не списывает единицу.

Денежная оплата подписки происходит независимо от использования: слово
«ТОЛЬКО» относится к единицам доступа, а не к регулярному платежу. Это явно
написано в тарифах, у согласия и в документах. Подписка не гарантирует
рекомендации ставки, выигрыш или доход.

Конечные начисления не сгорают после суток или отмены. Безлимит не накапливается,
но не расходует постоянный/бонусный баланс. Ответ, открытый по безлимиту,
сохраняется после его окончания. При безлимите нет прикладного дневного лимита
запросов; действуют общая очередь и защита от одновременных запросов.

Период начинается в момент успешной оплаты, не в полночь. Следующий платёж
не создаётся раньше завершения 72 часов. При задержке успешного ответа
используется время `captured_at`, если оно подтверждено; дубли не продлевают
период. Даты в кабинете показаны по МСК. После простоя более суток продление
останавливается; пропущенные дни не списываются задним числом.

## Внедрение сейчас — без включения автоплатежей

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.manage backup
git pull --ff-only origin main
sudo systemctl restart matchlab.service
```

По умолчанию `BILLING_RECURRING_ENABLED=false`. Код, тарифы и документы уже
доступны, кнопки подписки выключены, разовые продажи продолжают работать.
Существующие пользователи автоматически не подписываются. Схема дополняется;
старые заказы, начисления, покупки, сеансы и открытые ответы сохраняются.
Обновлённые общие документы требуют обычного подтверждения перед следующей
оплатой/ИИ-запросом; это не согласие на подписку.

## Что отправить менеджеру ЮKassa

Просим подключить автоплатежи для рабочего магазина prognozich.online.
Сервис продаёт доступ к информационным ИИ-разборам спортивных матчей, не
принимает ставки. Есть три тарифа 490 / 2 290 / 6 090 ₽ с периодом
72 часа. Первое подтверждение и сохранение карты происходят на странице
ЮKassa; последующие платежи — по сохранённому способу. Согласие отдельное,
не предустановлено. Отмена доступна в кабинете без обращения в поддержку.
Каждый платёж сопровождается кассовым чеком через подключённую кассу.

Публичные страницы:

- https://prognozich.online/static/legal/pricing.html
- https://prognozich.online/static/legal/offer.html
- https://prognozich.online/static/legal/recurring.html
- https://prognozich.online/static/legal/payment-refund.html
- https://prognozich.online/static/legal/privacy.html
- https://prognozich.online/static/legal/contacts.html

Дождитесь явного подтверждения включения автоплатежей **для рабочего магазина**.
Обычный доступ к API и `/me` не доказывают разрешение на автоплатежи.

## Включение после одобрения

```bash
cd /root/matchlab
.venv/bin/python scripts/configure_subscriptions.py --enable --yookassa-approved
sudo systemctl restart matchlab.service
```

Скрипт проверяет рабочий магазин/кассу чтением `/me`, сохраняет приватную копию
`.env` и меняет только флаг подписок. `--yookassa-approved` — явное указание
оператора, что разрешение получено; скрипт не может определить коммерческое
одобрение через `/me`. Новые ключи не нужны: используются реквизиты текущего
магазина. Никаких оплат проверка не создаёт.

Webhook остаётся прежним:
`https://prognozich.online/api/billing/yookassa/webhook`, события
`payment.succeeded`, `payment.canceled`, `refund.succeeded`.

После подключения проверьте реальный первый платёж/чек, карточку подписки,
время следующего платежа и отмену на собственном аккаунте. Локальные проверки
с фиктивным API не подтверждают разрешение магазина или регистрацию реального
чека. Без подтверждения не включайте флаг.

Приостановить новые подписки и новые автоматические списания:

```bash
.venv/bin/python scripts/configure_subscriptions.py --disable
sudo systemctl restart matchlab.service
```

Платежи с известным ID продолжают сверяться через GET, чеки — обрабатываться.
Неопределённый POST без ID после отмены или приостановки не повторяется: он
ждёт уведомления ЮKassa или ручной сверки поддержки; это исключает новое
фактическое списание после отзыва разрешения.
Оплаченный доступ и накопленный баланс продолжают действовать. Приостановка не отзывает
запрос, уже обрабатываемый банком.

## Управление, отказ и возвраты

Личный кабинет → Подписка → Отвязать карту и отменить подписку. Повторное подтверждение защищает
от случайного нажатия. После отмены новые списания не создаются, токен не
используется для будущих платежей. Успех уже начатого платежа выдаёт доступ,
но не возобновляет продление. Отмена и проверка доступны при выключенной
продаже подписок. Для новой подписки нужно новое согласие; одновременно может
быть только одно продление. Неопределённый предыдущий платёж блокирует новую
подписку до выяснения статуса.

Возвраты оформляются по исходному платежу в ЮKassa с чеком возврата.
Конечные единицы учитываются FIFO по цене своего начисления с распределением округления до копейки. Неиспользованный остаток виден в админке.
Для безлимита возврат за неиспользованную часть периода рассматривается по
времени и фактически предоставленным услугам согласно оферте/закону; это не
виртуальные единицы. Любой подтверждённый возврат отключает продление.
Возврат периода прекращает его безлимит; другие постоянные покупки не страдают.
Не следует возвращать платёж, уже возвращённый ранее, или начислять новые
единицы вручную вместо сверки исходного заказа.

В админке «Оплаты» видны подписки, продление, суммы и ближайший срок;
в заказе — зафиксированное согласие, его дата/редакция, чеки и начисления.
Платёжные токены не выдаются ни в пользовательский, ни в административный API.

## Гарантии исполнения и диагностика

- Цена, лимит и период выбираются сервером, фиксируются в подписке. Новая
  редакция тарифов не меняет существующее разрешение или цену продления.
- `save_payment_method=true` используется только для первого платежа после
  отдельного согласия. Продление — по `payment_method_id`, без новой формы.
- Платёж проверяется авторизованным GET: магазин, режим, сумма, валюта,
  оплаченный статус, заказ, пользователь и подписка должны совпасть.
- Запись платежа и его ключ сохраняются до HTTP. Повтор/перезапуск использует
  тот же `Idempotence-Key`. Уведомления не дают двойного начисления.
- Подтверждённый отказ останавливает автопродление без новых автоматических
  попыток оплаты и долга. Транспортная ошибка проверяется с прежним ключом.
- Через 23 часа неопределённый запрос переходит в проверку поддержки. Его
  нельзя пересоздавать вслепую после конечного срока хранения идемпотентности.
- `review` в админке требует сверки исходного ID/ключа в ЮKassa. Нужны действия
  поддержки; самостоятельный новый платёж не является исправлением старого.
- Если ЮKassa не сохранила карту, оплаченный доступ выдаётся, продление
  отключается и кабинет объясняет причину.
- Для 1/5 разборов применяются существующие предоплата/зачёт. Для безлимита
  передаётся одна услуга 24-часового доступа с `full_payment`, без НДС.
- Фоновый исполнитель работает в службе сайта; отдельный cron не нужен.
  Изолированные блокировки БД и уникальный номер периода защищают от дублей
  при нескольких экземплярах приложения.

Официальная схема:
https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments


## Скриншоты интерфейса для согласования ЮKassa

Если в рабочем магазине ещё нет подписок, администратор может открыть:
`https://prognozich.online/?billing_demo=1#account`.
Ссылка также есть в админке → Оплаты → «Показать сценарий отвязки карты · демо».

Демонстрация явно помечена вверху страницы и в самой карточке. Она показывает
тот же интерфейс, но не привязывает карту, не создаёт заказ или подписку,
не меняет реальный баланс и не обращается в ЮKassa. Пример состояния хранится
отдельно в настройке администратора; отмену можно сбросить кнопкой
«Начать демонстрацию заново». У обычных пользователей доступа к ней нет.

Для полного сценария сделайте три системных скриншота окна браузера на самом
рабочем сайте: кнопка «Отвязать карту и отменить подписку», подтверждение,
результат «Карта отвязана». Адрес должен быть полностью виден в строке браузера.
На macOS: Cmd+L раскрывает полный адрес, Cmd+Shift+3 снимает весь экран.
Снимок страницы через DevTools/Playwright не включает адресную строку.
Не включайте автоплатежи ради демонстрации. В сообщении ЮKassa укажите,
что показан демонстрационный сценарий интерфейса до включения рекуррентов.

## Смена тарифов на 3 дня

Новые ID: `three_days_three` (3 / 490 ₽), `three_days_fifteen` (15 / 2 290 ₽), `three_days_unlimited` (6 090 ₽). У всех период 72 часа, от подтверждённой оплаты. Схема базы не меняется. Старые `daily_*` остаются неизменными договорами на 24 часа: их цены, начисления, отложенные оплаты и продления не переводятся на новые условия автоматически. Новые подключения принимают только текущие планы и отдельное новое согласие. Разовые пакеты 1 / 490 ₽, 5 / 2 190 ₽ и 10 / 4 090 ₽ сохранены.

Стоимость 3 и 15 единиц не делится на копейки без остатка. Предоплата разбивается на позиции с разницей в 1 копейку; их сумма точно равна платежу. FIFO-открытия получают стоимость по накопительному округлению, последнее использует оставшиеся копейки. Чек зачёта и сумма неиспользованного остатка используют сохранённые стоимости.
