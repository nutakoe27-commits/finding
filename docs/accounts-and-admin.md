# Аккаунты и управление сервисом

Матчи, Live, коэффициенты, архив и краткая статистика открыты всем.
Регистрация по логину и паролю требуется для каждого ИИ-разбора, включая
прямой запрос к API. Проверка выполняется на сервере. Гостевая кнопка открывает
форму регистрации и продолжает выбранный разбор после входа.

Новые разборы, контекст и заметки принадлежат аккаунту. История и кэш разделены
по пользователям. Старые общие разборы сохраняются в базе, но автоматически
новым аккаунтам не назначаются и через личную историю не выдаются.
Независимый математический расчёт и просмотр данных остаются открытыми.

В карточке матча скрыты диагностические сведения; показаны короткие разделы
статистики, до трёх последних результатов каждого участника и до двух личных
встреч. Сокращение применяется в браузере: ИИ получает полные собранные и
проверенные разделы статистики провайдера. Обычная выборка архивной истории
для ИИ сохраняет до пяти результатов на участника и до трёх личных встреч.
Полнота зависит от доступности источников; блокировку StatsHub регистрация
и это обновление не устраняют.

## Обновление VPS

Этот этап устанавливается на VPS приложения. На сервере нейросети сборщики и
модель продолжают работать с прежней конфигурацией; протокол передачи архива
не меняется. Команды ниже выполняются на существующем VPS сайта:

```bash
cd /root/matchlab
git pull --ff-only origin main
.venv/bin/python -m pip install -r requirements.txt

# Онлайн-копия существующей SQLite, включая подтверждённые изменения WAL.
# Команда делает копию до применения миграции новой схемы.
.venv/bin/python -m matchlab.manage backup

# Сохраняет существующие сертификаты, ACME, upstream и запреты worker API.
# Добавляет HTTPS-перенаправление и отдельный лимит попыток входа.
sudo .venv/bin/python scripts/update_accounts_nginx.py --check
sudo .venv/bin/python scripts/update_accounts_nginx.py

sudo systemctl restart matchlab.service
curl -fsS http://127.0.0.1:8080/api/auth/me

# Пароль вводится скрыто в терминале, а не аргументом или сообщением в чат.
.venv/bin/python -m matchlab.manage create-admin site_admin
```

Ответ `/api/auth/me` без cookie содержит `user: null`; это нормально.
Откройте `https://prognozich.online`, войдите как `site_admin` и нажмите
«Управление» в верхней панели. Прямая страница: `/#admin`.

Не запускайте базовую HTTP-настройку домена поверх существующего HTTPS.
Обновляющий скрипт работает только с управляемой конфигурацией Matchlab и
отказывает при неизвестном виртуальном хосте или отсутствии настроенного TLS.
Он сохраняет копию, проверяет `nginx -t`, перечитывает Nginx и восстанавливает
прежнюю конфигурацию при ошибке.

По умолчанию `PUBLIC_ORIGIN=https://prognozich.online`. Для другого адреса
задайте его канонический HTTPS origin в `.env` и используйте соответствующий
`--domain` при обновлении Nginx. Все приведённые команды рассчитаны на текущую
установку приложения в `/root/matchlab` от root. Если ваша `matchlab.service`
использует другого пользователя, команды создания аккаунтов и ключей запускайте
с правами этого пользователя и теми же настройками базы, что у приложения.

## Разделы админ-панели

- **Обзор:** реальные регистрации, входы, уникальные браузеры, события просмотра,
  успешные и неуспешные ИИ-запросы, время ответа, переходы в Winline,
  подписчики, принятые push-службой сообщения и активации кодов. Периоды
  7/30/90 дней, график посещаемости и выгрузка итогов CSV.
- **Пользователи:** поиск, дата регистрации/входа, число разборов, бонусы,
  ограничение и восстановление доступа. Ограничение отзывает текущие сеансы.
  Роли администраторов через веб-интерфейс не назначаются и не отключаются.
- **Уведомления:** черновик, предпросмотр, сегмент, отложенное время,
  подтверждение точного числа подписанных устройств, очередь, отмена
  неотправленной части, счётчики принятия и ошибок. Аудитории: все подписчики,
  входившие за 7 дней или только устройства текущего администратора для теста.
- **Промокоды:** черновики, включение/пауза, даты действия, общий лимит,
  бонусные разборы, счётчик активаций. Один аккаунт активирует код один раз;
  параллельные запросы не превышают общий лимит и не удваивают бонус.
- Внешние партнёрские переходы и их редактор отключены.
- **Журнал:** подтверждения администратора, изменения пользователей, кодов,
  настроек сервиса и кампаний. Пароли и личные заметки сюда не записываются.

Пустые показатели означают отсутствие событий, а не демонстрационные данные.
Статистика посещаемости начинает накапливаться после обновления; она не
восстанавливается задним числом. График использует UTC, подписи времени
админ-панели — часовой пояс браузера. Путь пользователя показывает число
событий, не когортную конверсию. «Принято push-службой» не подтверждает прочтение
или фактический показ на устройстве.

## Безопасность аккаунтов

Пароли: scrypt с индивидуальной случайной солью. В базе хранится только хэш
случайного session token. Cookie HttpOnly, SameSite=Lax, Secure на HTTPS,
без Domain; срок сеанса — 7 дней. Смена пароля завершает остальные сеансы.
Привилегии читаются из базы, не из клиентских полей. Есть защита CSRF,
проверка origin, лимиты попыток и запросов к ИИ, запрет встраивания страницы
во фреймы и CSP без встроенных/сторонних скриптов.

Изменения доступа, промокодов, ссылок и отправки требуют повторного пароля
администратора; подтверждение действует 10 минут в конкретном сеансе.
Администратор создаётся только локальной командой. Первый зарегистрированный
посетитель не становится администратором. Пароли восстановления, OAuth и
сброс через email сейчас не включены.

Восстановление через терминал VPS:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.manage list-admins
.venv/bin/python -m matchlab.manage set-password site_admin
# Или только отозвать сеансы:
.venv/bin/python -m matchlab.manage revoke-sessions site_admin
```

Приложение должно слушать loopback; публичный трафик идёт через Nginx.
Заголовок `X-Real-IP` доверяется только от loopback, где Nginx заменяет его
реальным адресом клиента. Прямой публичный порт приложения открывать не нужно.

## Push на VPS

Web Push работает через HTTPS и добровольное разрешение в браузере.
На iOS доступность зависит от браузера и установки веб-приложения на главный
экран. Код не просит разрешение автоматически при открытии сайта.

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.manage init-push
sudo systemctl restart matchlab.service
sudo .venv/bin/python scripts/install_push_worker.py --check
sudo .venv/bin/python scripts/install_push_worker.py
sudo systemctl status matchlab-push.service --no-pager
```

`init-push` создаёт P-256 ключ в каталоге данных с правами `600` и добавляет
`WEBPUSH_*` в `.env`, сохраняя настройки модели и сборщиков. Повторный запуск
сохраняет существующий ключ. Закрытый ключ не выводится и не коммитится.
При переносе сохраняйте `.env`, ключ и рабочую базу вместе; произвольная
смена ключа потребует новых браузерных подписок.

Очередь запускается как отдельная `matchlab-push.service` от пользователя
приложения, с лимитом 256 MiB RAM и 20% одного CPU. Существующие службы модели,
сборщиков и туннеля она не перезапускает. В панели отдельно видны настройка
ключей и свежесть отчёта службы доставки.

Для проверки войдите как администратор → личный кабинет → включите уведомления
на своём устройстве. В панели создайте кампанию с аудиторией «Только мои
устройства», проверьте предпросмотр и подтвердите отправку. Затем можно
использовать другие сегменты. Получатели фиксируются при подтверждении;
кампания не расширяется на зарегистрировавшихся позже пользователей.

Доставка использует шифрование Web Push и VAPID. Разрешены только известные
push-шлюзы браузеров, HTTP redirects запрещены. Ответы 404/410 отключают
истёкшую подписку; 429 и временные серверные ошибки повторяются с увеличением
паузы, максимум 5 попыток. Аренда задачи позволяет восстановиться после
падения worker. При сетевой неопределённости возможна повторная передача;
notification tag объединяет сообщения одной кампании на устройстве.
Отмена не отзывает уже принятые сообщения; начатая отправка может завершиться.

## Промокоды и будущие ограничения

Промокоды начисляют бонусные разборы. `AI_DAILY_LIMIT=0` по умолчанию оставляет
дневной доступ после регистрации без ограничений; кратковременные лимиты
запросов продолжают защищать ИИ от перегрузки. Если позже включить дневной
лимит в `.env`, бонусы расходуются после него. Ошибочные запросы бонусы не
списывают. Это бонусный баланс, не платёжная система и не денежная скидка.
Активация доступна в личном кабинете.

## Служебные ссылки и способы входа

Внешние переходы отключены. Старые адреса `/go/winline/ID?source=stream|legacy`
сохранены для совместимости с ранее опубликованными ссылками: они ведут только
на нашу страницу `/match/ID/slug`, без внешнего назначения. Параметр `url` и
ранее сохранённый партнёрский шаблон игнорируются. Редактор удалён из интерфейса;
`GET /api/admin/links` сообщает `enabled=false`, изменение возвращает HTTP 410.

Таблица `user_identities(provider,subject,user_id)` отделяет учётную запись
от способа входа и готова для привязок Яндекса и Mail. Сами OAuth-провайдеры
пока не включены: позже потребуются приложения провайдеров, client credentials,
redirect URI и отдельная проверка безопасного связывания аккаунтов.

## Проверки

```bash
PYTHONPATH=tests python -m unittest discover -s tests -q
python tests/browser_accounts_smoke.py
python tests/browser_design_smoke.py
```

Тесты используют временные базы, локальный ответ ИИ и имитацию HTTP транспорта
push-службы. Внешним пользователям тестовые кампании не отправляются.
