# Scrapy: рынки спортивных событий Winline

Сборщик работает на сервере Qwen, приёмник и интерфейс — на VPS. BetBoom
не опрашивается. Установленные vLLM, Nginx, Docker и туннель модели не меняются.
Используется отдельный ранее настроенный SSH-туннель на `127.0.0.1:18081`.

Scrapy ведёт очередь страниц линии, турниров и событий. Playwright открывает
JavaScript-страницы в одном браузере с ограниченным числом вкладок. Текущие
ссылки берутся из самой линии; числовые ID не перебираются. Winline меняет
короткий `/stavki/event/ID` на канонический адрес вроде
`/stavki/sport/futbol/angliya/apl/ID`; это нормальный переход.

На странице встречи выбирается вкладка «Все». Сборщик раскрывает только
заголовки рынков, читает исходы, прокручивает страницу и проверяет стабильность
структуры. Кнопки коэффициентов не нажимаются. Источник — публичные страницы,
без входа в аккаунт и обхода проверок доступа.

## Что хранится

У каждого рынка сохраняются название, группа, период, параметр и исходы.
У исхода — подпись, коэффициент, параметр и состояние доступности. Таймы,
индивидуальные тоталы, разные значения форы и комбо остаются отдельными
вариантами. Приостановленный исход сохраняется с соответствующим состоянием.

Полный снимок страницы требует активной вкладки «Все», раскрытых групп,
стабильных проходов до конца страницы и учёта всех найденных кнопок исходов.
Неизвестные подписи и недоступные группы делают снимок неполным. Такой набор
не заменяет прежний полный снимок и не получает отметку полного успеха.

На VPS хранится последний полный набор по событию в сжатом виде; повторный
неизменившийся набор обновляет время наблюдения без создания полной архивной
копии. Старые 1X2-наблюдения и прогнозы сохраняются отдельно. Тройка
«Исход 1X2 → осн.время» дополнительно поступает в прежнюю линию для прогнозов.
Прогнозная модель по-прежнему поддерживает основной исход АПЛ; сбор прочих
рынков сам по себе не означает наличие модели для каждого из них.

## Установка

Сначала обновите **VPS**:

```bash
cd /root/matchlab
git pull --ff-only origin main
systemctl restart matchlab.service
curl -fsS http://127.0.0.1:8080/api/bookmakers/events
```

Новых Python-пакетов на VPS не требуется. Таблица рынков добавляется при
запуске, остальные данные не удаляются. Отдельный ключ приёмника уже настроен
предыдущими шагами; создавать новый ключ не нужно.

Затем **на сервере Qwen**, под `user`:

```bash
cd ~/matchlab-scraper-src
git pull --ff-only origin main
sudo bash scripts/install_market_crawler.sh --api-url http://127.0.0.1:18081
```

Нужны Python 3.11+ с venv, действующий SSH-туннель и root-owned файл
`/etc/matchlab-scraper-token.env` с правами 600. Установка до изменений
проверяет минимум 6 ГиБ свободной RAM. На вашем сервере Qwen было доступно
51 ГиБ; VPS с 961 МиБ RAM для этой службы не используется.

Код и отдельное окружение устанавливаются в `/opt/matchlab-crawler`,
кэш проверенных документов — в `/var/lib/matchlab-crawler/events`.
Прежний браузерный кэш переиспользуется. Пакеты ОС автоматически не обновляются.
Служба ограничена 4 ГиБ RAM и двумя CPU, работает под `matchlab-scraper`
с низким приоритетом и без доступа к GPU. Scrapy remote control и telnet
отключены. Ключ приёмника не наследуется Chromium.

По умолчанию открываются до четырёх страниц. Есть `--concurrency 1..8` для
установщика. Сначала `matchlab-crawler-check` должен получить и доставить
хотя бы один полный снимок страницы. Только после этого прежний управляемый
`matchlab-scraper` выключается и включается `matchlab-crawler`.
Проверка одной страницы не объявляет весь каталог собранным.

При неудаче журнал проверки печатается сразу. Новая основная служба не
включается. `--install-only` устанавливает код без проверки/запуска,
`--dry-run` только проверяет ресурсы и аргументы.

Установщик выводит шесть этапов и ход установки Python-пакетов. Первая
загрузка зависимостей может занять несколько минут, проверка Winline — до
четырёх минут. В прежней версии после проверки памяти `pip` работал с
подавленным выводом. Если такой запуск ещё выполняется, его процессы можно
посмотреть во втором SSH-сеансе:

```bash
pgrep -af 'install_market_crawler|/opt/matchlab-crawler/'
```

Пустой список рынков до первой успешной доставки ожидаем. Сам по себе он
не определяет причину задержки. Пока установка выполняется, второй установщик
запускать не нужно. После прерывания на этапе пакетов повторный запуск
использует уже загруженные зависимости.

## Интервал и полнота обхода

Целевой интервал между началами циклов — 60 секунд. Циклы не накладываются.
Если полный обход занимает дольше, следующий начинается сразу после него.
Значение `cycle_seconds` показывает измеренное время, а не обещание обновления
всего каталога за минуту. Старейшие или ещё не собранные события получают
приоритет в очереди.

Обход идёт по обнаруженным публичным страницам выбранных видов спорта и ссылкам
текущей главной. По умолчанию включены все обычные виды спорта; киберспорт и
виртуальные игры отбрасываются. Подробности обновления: [sports.md](sports.md).
Ленивая подгрузка и виртуальные списки обрабатываются с ограничениями:
до 5000 событий, 200 страниц списка и 200 шагов прокрутки на страницу.
Достижение ограничения, ошибка страницы или неполный набор исходов отражаются
в отчёте; это не считается полным успешным циклом. Счётчик найденных событий
не подменяет официальную общую численность каталога букмекера.

В интерфейсе раздел «Рынки Winline» показывает события, полноту и время
каждого снимка. Раскрытие встречи загружает её рынки; есть поиск и отдельные
периоды/параметры. Возраст считается от начала чтения страницы. После трёх
минут снимок помечается устаревшим, даже если процесс Scrapy продолжает работать.

## Проверка работы

На сервере Qwen:

```bash
sudo systemctl status matchlab-crawler matchlab-scraper-tunnel --no-pager
sudo journalctl -u matchlab-crawler -n 30 --no-pager
sudo cat /var/lib/matchlab-crawler/cycle-status.json
```

Последний файл содержит только счётчики и время: `discovered_events`,
`saved_events`, `complete_events`, `published_complete_events`,
`failed_events`, `incomplete_events`, `cycle_seconds`, `traversal_complete`.
`success` у проверки означает готовность одной полной страницы и приёмника;
у полного цикла дополнительно требуются завершённый обход и отсутствие
неполных/ошибочных страниц.

На VPS доступны:

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/bookmakers/events?limit=50&offset=0` | Лёгкий список без массивов исходов |
| GET | `/api/bookmakers/events/ID/markets` | Все сохранённые рынки выбранной встречи |
| POST | `/api/bookmakers/events/ingest` | Loopback-приёмник с ключом сборщика |

Для просмотра live и начавшихся встреч у списка есть `include_started=true`.
Пустой или ошибочный документ не удаляет прежние данные. На сервере Qwen
проверенные полные и частичные наборы хранятся раздельно в `events/`.

Обновление: остановите только `matchlab-crawler`, обновите Git и повторите
установщик. Для остановки: `sudo systemctl disable --now matchlab-crawler`.
Туннель модели, vLLM и веб-сервисы других проектов для этих команд не нужны.

## Проверки разработки

В базовом окружении выполняются тесты API, хранения и валидации рынков.
Дополнительное окружение `requirements-crawler.txt` проверяет настоящий
Scrapy + scrapy-playwright + Chromium на локальном HTTP-сайте. Тестовые HTML
построены по публичным меткам, периодам, ценам и классам из отчёта пользователя.
Проверяются вкладка «Все», раскрытие заголовков, разделение таймов/параметров,
учёт каждого исхода, запрет ложной полноты, и отсутствие нажатий на цены.
Доступ и полнота текущего сайта дополнительно проверяются на пользовательском
сервере установщиком и отчётом полного цикла.
