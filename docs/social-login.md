# Яндекс ID, ВКонтакте, Одноклассники и Mail.ru

Используются Яндекс OAuth и единое веб-приложение VK ID для кнопок ВК, ОК и
Mail.ru. Кнопки появляются после настройки соответствующего приложения.
Обычный вход/регистрация доступны по дополнительной кнопке; пароли существующих
аккаунтов, баланс, покупки, история и открытые ответы сохраняются.

## Что нужно от владельца

### Яндекс

Создайте веб-приложение на https://oauth.yandex.ru/ . Название: **prognozich ai**,
адрес сервиса: **https://prognozich.online**. Запрашивается только базовый
профиль `login:info`; e-mail, телефон и доступ к почте для входа не нужны.

Redirect URI (в точности, без `#`, завершающего `/` и дополнительных параметров):

`https://prognozich.online/api/auth/social/yandex/callback`

Понадобятся **Client ID** и **Client secret**. Секрет вводится только на VPS.
Если кабинет требует публикацию/подтверждение домена, завершите этот шаг.

### VK ID — одно приложение для трёх кнопок

Создайте приложение типа **Web** в кабинете подключения VK ID:
https://id.vk.ru/about/business/go . Укажите адрес сайта и доверенный origin
**https://prognozich.online**. Включите доступные способы **ВКонтакте,
Одноклассники и Mail.ru**, базовый профиль `vkid.personal_info` и завершите
необходимую публикацию приложения. Права на телефон и e-mail не запрашиваются.

Redirect URI:

`https://prognozich.online/api/auth/social/vkid/callback`

Понадобится **ID приложения**. Обмен кода выполняется сервером с PKCE S256;
секретный ключ VK ID в этой схеме не используется и не помещается в браузер.

Иконка приложения: https://prognozich.online/static/auth/service-avatar.png
Политика: https://prognozich.online/static/legal/privacy.html
Соглашение: https://prognozich.online/static/legal/terms.html

## Установка на VPS

```bash
cd /root/matchlab
git pull --ff-only origin main
.venv/bin/python scripts/configure_social_login.py yandex
.venv/bin/python scripts/configure_social_login.py vkid
sudo .venv/bin/python scripts/configure_social_proxy.py
sudo systemctl restart matchlab.service
```

Можно подключать сервисы по одному. Скрипт сохраняет приватную резервную копию
`.env`, записывает только выбранные параметры и не меняет базу, кассу или модель.
Новые поля пользователей и служебные таблицы добавляются при запуске приложения.
Пароли и ранее открытые ответы не сбрасываются. Способ последнего входа
отображается у пользователя в админке; подробная статистика входов не собирается.

`configure_social_proxy.py` меняет только управляемый файл виртуального хоста
Matchlab: исключает query callback из access log, проверяет `nginx -t`, перечитывает
Nginx и откатывает файл при ошибке. TLS, порт, заголовки и другие сайты сохраняются.
Для вручную написанного Nginx-конфига скрипт откажется от изменения: добавьте
отдельный callback location с прежним proxy_pass и `access_log off` самостоятельно.
Приложение также удаляет query из callback-логов и ставит Referrer-Policy=no-referrer.

Проверка доступности без авторизации:

```bash
curl -fsS https://prognozich.online/api/auth/social/providers
```

Затем проверьте каждый вход на реальных аккаунтах. До настройки приложений
локальные проверки используют фиктивный API; они не подтверждают публикацию
или разрешения приложений на стороне провайдеров.

## Мобильный вход и существующие покупки

Кнопки открывают официальную HTTPS-авторизацию в той же вкладке. Не создаются
попапы, которые мобильный браузер может блокировать. Провайдер использует свою
активную сессию или предлагает приложение, если это поддерживается текущими
браузером, приложением и настройками ОС. Гарантировать открытие установленного
приложения из любого браузера невозможно; при отсутствии такой возможности
остаётся обычный вход у провайдера. Параметры принудительной повторной выдачи
согласия Яндекса не включаются. Для ОК/Mail выбирается соответствующий внешний
провайдер VK ID, как в официальном многобрендовом потоке VK ID.

Новый пользователь подтверждает соглашение, обработку данных и возраст один раз
после проверки личности; локальный пароль вводить не нужно. Известная привязка
входит сразу. Для уже существующего аккаунта с покупками сначала войдите по
старому логину, затем откройте **Личный кабинет → Способы входа → Подключить**.
Для аккаунта с паролем требуется его подтверждение. Аккаунты не объединяются по
имени или совпавшему e-mail; чужая привязка не переносится на другой аккаунт.
ВК/ОК/Mail, вернувшие один и тот же VK ID, используют один аккаунт сервиса.
Разные VK ID можно явно подключить к одному своему аккаунту из его настроек.

Состояние входа одноразовое, привязано к HttpOnly/SameSite cookie, ограничено
10 минутами и защищено PKCE. Provider access/refresh tokens не сохраняются.
Неподтверждённые ID из браузера не принимаются; роль администратора не выдаётся
при регистрации. Аккаунт, отключённый администратором, не сможет обойти блокировку.
