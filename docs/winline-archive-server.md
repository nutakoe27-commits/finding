# Локальная история Winline на сервере нейросети

Установка выполняется **в приложении «Ассистент» на самом сервере**. Вход по SSH с Mac или из облачного чата не требуется. Нужны Linux с systemd, Python 3.11+ с venv, административные права, не менее 3 ГиБ доступной RAM и 5 ГиБ свободного места на разделе `/var/lib`. Диск должен иметь запас для роста истории. GPU сборщику не нужен.

Это отдельный модуль: он сохраняет SQLite рядом с моделью, не меняя `matchlab-crawler`, `matchlab-statistics`, SSH-туннели, сайт или службу модели. Публичный сетевой порт не открывается. Уже существующий сайт продолжит пользоваться своим прежним источником; новая база не подключается к его API автоматически.

Для подключения будущих и Live-матчей, истории и контекста ИИ к сайту выполните
[инструкцию обновления обоих серверов](archive-integration.md). Она добавляет
отдельную передачу через существующий туннель; одной базовой установки ниже
для появления данных в интерфейсе недостаточно.

## Установка через приложение на сервере

Откройте терминал сервера через приложение «Ассистент». Если репозиторий уже находится в `~/matchlab-scraper-src`:

```bash
cd ~/matchlab-scraper-src
git pull --ff-only origin main
sudo bash scripts/install_winline_archive.sh --dry-run
sudo bash scripts/install_winline_archive.sh
```

Если копии нет, сначала выполните:

```bash
git clone https://github.com/nutakoe27-commits/finding.git ~/matchlab-scraper-src
```

Если системный `python3` старше 3.11, укажите установленный новый интерпретатор: `sudo bash scripts/install_winline_archive.sh --python /usr/bin/python3.12`. Окружение модели не используется для установки пакетов.

Установщик создаёт только:

- отдельного пользователя `winline-archive`;
- код и Python-окружение в `/opt/winline-archive`;
- базу, кэш браузера, журнал состояния и резервные копии в `/var/lib/winline-archive`;
- службу `winline-archive.service` с автозапуском после перезагрузки.

Проверка `--dry-run` ничего не устанавливает и не обращается к Winline. Обычная установка скачивает Chromium и проводит реальную проверку источника в отдельной `probe.sqlite3`. Рабочая база при проверке не изменяется. Автосбор включается только после свежего успешного ответа с событиями. При ошибке новой службы не будет запущено; причина видна в выводе команды и `status.json`. При отсутствующих библиотеках Chromium установщик покажет отдельную команду установки зависимостей.

Проверка источника проводится с ограничениями ресурсов и изоляцией, соответствующими службе. Доступ из облачного чата не подтверждает доступ с IP вашего сервера. При отказе источника никакой обход блокировки или изменение прокси автоматически не выполняются.

При повторной установке останавливается только собственная `winline-archive.service`. Код и окружение обновляются на месте; рабочая база, расписание и копии остаются. При ошибке обновления собственная служба может остаться остановленной; остальные службы установщик не перезапускает.

## Накопление

Первый цикл сначала запрашивает доступный архив примерно за 30 дней, затем
обычные дополнительные рынки. Первые результаты передаются на сайт по мере
получения, не ожидая окончания обхода рынков. Полный проход может занять десятки
минут и дольше. Затем отдельно собираются объявленные рынки игроков и
долгосрочных исходов. Полный цикл повторяется не чаще чем через шесть часов
после завершения предыдущего. При следующих полных циклах повторно проверяются
последние два доступных дня архива каждого спорта; старые сохранённые результаты
не удаляются. Более поздние исправления давних результатов потребуют отдельного
запуска с большим `--history-days` при остановленной службе.

Между полными циклами браузер наблюдает основной поток пятиминутными сессиями со снимками примерно раз в 10 секунд. Запуски одного worker не перекрываются; при долгом цикле следующий ждёт его окончания. Расписание сохраняется при перезагрузке. Служба не запускает дополнительные браузеры для параллельных задач. Не запускайте ручной `collect.py` на её базу одновременно с worker.

Снимки основного потока сохраняются также во время полного и дополнительного
обходов. Короткий проход проверяет последний доступный день результатов каждого
спорта. При подключённой передаче недавно открытые в интерфейсе события
дополнительно запрашиваются примерно раз в 20 секунд, до четырёх одновременно.

Служба использует `--light-snapshots`: в частом снимке сохраняются все текущие
события и их основные рынки, дополнительные рынки недавно открытых матчей и
новые ответы полного обхода. Прочие сохранённые линии остаются в базе с прежним
временем наблюдения. Это уменьшает размер частой записи и не требует заново
обрабатывать всю накопленную коллекцию рынков каждые 10 секунд. Число линий
одного снимка может быть намного меньше общего числа строк `lines`.
Отложенные между снимками ответы полного обхода накапливаются и сохраняются
при следующем снимке, в том числе принудительно в конце обхода.
Обычный ручной `collect.py` без этого флага сохраняет все полученные линии.

Обычные, архивные и дополнительные записи обновляются по ключам; история наблюдавшихся изменений сохраняется. Заполнение базы не обучает веса нейросети. Для анализа нужны выборка фактов и запрос к существующему API модели.

Пустые и неполные ответы остаются явными состояниями. `partial` означает частичный результат, а не подтверждение полноты сайта. После ошибок предусмотрена пауза с увеличением до часа. После частичного полного цикла следующий полный цикл ждёт обычный интервал; просмотр основного потока продолжается.

Служба ограничена 2 ГиБ RAM, половиной одного CPU, низким приоритетом CPU/диска и отсутствием доступа к GPU-устройствам. При доступном месте менее 2 ГиБ новые циклы приостанавливаются с `storage_low`. Во время активного обхода свободное место может продолжать уменьшаться, поэтому размер диска нужно контролировать. Автоматического удаления исторических событий и коэффициентов нет.

`present_in_latest_snapshot` означает наличие в последнем снимке конкретного клиента. Быстрая сессия не загружает все дополнительные рынки, поэтому отсутствие в ней не доказывает снятие рынка с сайта. Прежние строки и их время остаются в `lines` и `line_history`; `odds --include-missing` показывает также предыдущие наблюдения. Не выдавайте их за актуальные предложения.

## Проверка работы

```bash
sudo systemctl status winline-archive --no-pager
sudo journalctl -u winline-archive -n 40 --no-pager
sudo cat /var/lib/winline-archive/status.json
```

В `status.json` есть время обновления, текущая задача, результат последнего запуска и информация о резервной копии. `collecting` — задача выполняется; `ok` — подтверждён новый успешный запуск; `partial`, `error`, `backup_error`, `storage_low` требуют просмотра деталей. Состояние нужно читать вместе со временем и состоянием службы. Один старый успешный статус не подтверждает продолжающийся сбор.

Чтение базы:

```bash
cd /opt/winline-archive
sudo -u winline-archive env WINLINE_DATABASE=/var/lib/winline-archive/winline.sqlite3 \
  .venv/bin/python -m winline.query stats
sudo -u winline-archive env WINLINE_DATABASE=/var/lib/winline-archive/winline.sqlite3 \
  .venv/bin/python -m winline.query events --limit 10
```

`WINLINE_DATABASE` задаёт путь для локальных CLI и Python-запросов. Данные в GitHub не записываются. Новая серверная база заполняется источником самостоятельно; прежняя база из облачного чата автоматически на сервер не переносится.

## Контекст для вашей модели

Получите ID предстоящих событий:

```bash
cd /opt/winline-archive
sudo -u winline-archive env WINLINE_DATABASE=/var/lib/winline-archive/winline.sqlite3 \
  .venv/bin/python -m winline.query sql \
  "SELECT id,members_json,start_at FROM matches WHERE present_in_latest_snapshot=1 AND is_live=0 AND datetime(start_at)>datetime('now') ORDER BY start_at LIMIT 10"
```

Подставьте ID из вывода вместо `ID_СОБЫТИЯ`:

```bash
sudo -u winline-archive env WINLINE_DATABASE=/var/lib/winline-archive/winline.sqlite3 \
  .venv/bin/python -m winline.team_context --event ID_СОБЫТИЯ --messages \
  --output /var/lib/winline-archive/context.json
```

Файл содержит `messages` для OpenAI-совместимого локального API: два участника, до десяти результатов каждого, до пяти личных встреч, ограниченную подборку наблюдений рынков, время и ограничения источника. Команда сама не вызывает и не настраивает модель. Его нужно передать в поле `messages` вашего существующего клиента. Это не автоматическое подключение новой истории к интерфейсу prognozich ai.

Контекст предназначен для предматчевого анализа. `--as-of` принимает ISO-время с часовым поясом. Событие и факты должны быть наблюдены к этому моменту; поздние исправления счёта и цен не используются. Архивный результат, впервые собранный сегодня, не считается известным месяц назад. Начавшиеся события отклоняются: для них нельзя выдавать ретроспективные факты за предматчевые.

Участники сопоставляются по полному нормализованному имени внутри спорта; алиасы не объединяются автоматически. Отсутствие совпадений не означает отсутствие игр. Текст счёта и шаблоны рынков сохраняются без выдуманных правил расчёта. Травмы, составы, новости и подробная статистика внешних виджетов отсутствуют. Контекст улучшает доступ к фактам, но качество прогнозов проверяется отдельно на последующих матчах.

## Копии и восстановление

Раз в сутки после успешного или частичного цикла создаётся согласованная копия SQLite через backup API, включая подтверждённые записи WAL. Она проверяется и сжимается; сохраняются семь последних завершённых копий. Ротация затрагивает только эти копии, не рабочую историю. При нехватке места старые исправные копии не удаляются ради создания новой.

Файлы находятся в `/var/lib/winline-archive/backups/`, рядом — SHA-256 несжатой базы. Эти копии находятся на том же сервере и не защищают от потери диска; отдельную внешнюю копию следует настроить средствами вашей инфраструктуры.

Восстановление выполняется только в новый файл, без перезаписи существующей базы:

```bash
cd /opt/winline-archive
sudo -u winline-archive .venv/bin/python -m winline.backup restore \
  --archive /var/lib/winline-archive/backups/ИМЯ_КОПИИ.sqlite3.gz \
  --database /var/lib/winline-archive/restored.sqlite3
```

Сначала проверьте восстановленный файл. Замену рабочей базы выполняйте отдельно при остановленной только `winline-archive.service`.

Для остановки именно этого сборщика:

```bash
sudo systemctl disable --now winline-archive.service
```
