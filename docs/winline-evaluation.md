# Проверка независимых прогнозов Winline

Это проверка текущей модели `independent-football-v19`, которая выдаёт проценты
в карточке матча. Старый `python -m matchlab backtest` проверяет другую модель
на CSV английской лиги и не заменяет эту проверку.

В админке откройте **Качество прогнозов**. Выборка по умолчанию — 10 игр.
В отчёте видны все три вероятности, фактический счёт, попадание фаворита,
число оценённых/пропущенных игр, Brier, log loss, равномерный ориентир и интервал
Уилсона для доли попаданий. Brier и log loss оценивают полный расклад П1/Х/П2;
меньше — лучше. Интервал доли попаданий не является интервалом вероятности
одного матча. Связанные рынки не считаются независимыми играми.

## 1. Сохранённые предматчевые прогнозы

Основной режим `saved`: берётся первый сохранённый независимый прогноз текущей
версии модели для каждой встречи, созданный **до** её начала. Проверяются время
рыночного снимка и время/фаза подробной статистики. Live, завершённая статистика,
неизвестное время статистики, старые версии расчёта и дубли пользователей
исключаются. Результат сопоставляется по спорту, обоим участникам, турниру и
времени начала с допуском 120 секунд; неоднозначное совпадение не засчитывается.

Используется сохранённый расклад, не новый прогноз по сегодняшней странице.
В этом режиме можно проверить и рекомендованные рынки, если их точные условия
сохранены и в результате есть нужный период. Возврат отделяется от выигрыша,
отсутствующий счёт тайма не заменяется половиной итогового счёта.

На VPS сайта:

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.winline_backtest \
  --mode saved --limit 10 \
  --output data/evaluations/winline-saved-10.json
```

Если подходящих предматчевых снимков меньше десяти, отчёт прямо показывает это.
Нулевой результат проверки не подменяется автоматически реконструкцией.
Чтобы получить полноценную проверку новых аргументов и восьми популярных рынков,
нужно сохранить разборы десяти матчей **до начала**, затем выполнить проверку
после получения результатов. Уже существующая кнопка «Разбор ИИ» сохраняет
необходимые данные: подробную статистику, условия популярных рынков, проценты
и ответ модели. Проверка вероятностей не требует повторного вызова Qwen.

## 2. Реконструкция по архиву результатов

Режим `historical-results` полезен для начальной проверки, когда предматчевых
снимков нет. Последние десять допустимых футбольных результатов выбираются
**до** проверки пригодности модели. Если участнику не хватает истории,
матч остаётся в таблице как неоценённый и не заменяется более удобным.

Для каждого матча используются только более ранние результаты с отступом
24 часа; текущая встреча, следующие результаты, нынешние сезонные средние,
таблица, текущая форма и статистика целевой игры не используются.
Применяются текущие правила независимой модели и лимит выборки 1500 записей.
При этом не доказаны доступность и версии исторических данных на тот момент:
такой прогон нельзя представлять как настоящий предматчевый тест.

```bash
cd /root/matchlab
.venv/bin/python -m matchlab.winline_backtest \
  --mode historical-results --limit 10 \
  --output data/evaluations/winline-reconstruction-10.json
```

Команда читает существующую БД в режиме `mode=ro` и сохраняет только отчёт JSON
и CSV. Не запускает браузер, не скачивает страницы, не вызывает нейросеть и
не меняет службы. Можно явно указать `--database /путь/к/winline.sqlite3`:
поддерживаются и база приложения на VPS, и исходная база архива Winline.
Для запуска требуются обычные зависимости приложения, включая numpy/scipy.

Без сохранённых популярных рынков нельзя восстановить их исторические линии:
реконструкция проверяет только 1X2. Нельзя взять сегодняшние форы/тоталы и
выдать их за условия прошлой игры. Выгрузка всей сегодняшней статистики
завершённого матча также не восстанавливает её предматчевое состояние.

## Первый реальный прогон

В [evaluation_results/winline/2026-11-10-pilot](../evaluation_results/winline/2026-11-10-pilot/README.md)
сохранены JSON, CSV и таблица по реальной архивной выгрузке из рабочей среды,
а не из производственной БД пользователя. Из десяти заранее выбранных игр
оценены девять, наиболее вероятный исход совпал в пяти случаях; один матч
не оценён. Brier — 0,534 против 0,667 для равномерного ориентира; log loss —
0,908 против 1,099. Интервал Уилсона доли попаданий — 26,7–81,1%.
Этого недостаточно для вывода о калибровке или преимуществе над сильным ориентиром.

В архивном счёте вида `2:1 (1:0 1:1)` теперь читаются итог и оба тайма,
только если сумма таймов совпадает с итогом. Раньше модель принимала лишь
`2:1`, теряя стандартные записи архива. Неоднозначные периоды, дополнительное
время, пенальти и технические результаты не превращаются в основное время.

## Ограничения

Десять игр — проверка работоспособности и грубых ошибок. Для оценки точности
процентов нужны сотни и больше последующих матчей без настройки модели на
проверяемых результатах. Равномерный ориентир прост; превосходство над ним
на девяти играх не доказывает качество продукта. Доходность не рассчитывается
без сохранённых исторических цен. Коэффициенты не используются для прогноза.

Проверка доступна только администратору, не раскрывает пользователей и заметки.
Формулы, интенсивности и параметры модели в интерфейсе отсутствуют.
