# Индексируемые страницы матчей

У каждой сохранённой карточки матча есть постоянный URL
`/match/{id}/{названия-участников}`. В HTML сразу присутствуют участники,
турнир, дата и время МСК, состояние встречи, доступные показатели источника
и снимок коэффициентов. JavaScript не нужен для чтения страницы. Название,
description, canonical, Open Graph, SportsEvent и BreadcrumbList индивидуальны.
Неизвестные адреса возвращают 404 с noindex; старые/неверные варианты slug
перенаправляются на текущий canonical. Query-параметры не создают canonical-дубли.

Текст «прогноз ИИ» используется для доступного предматчевого разбора
поддерживаемого спорта. Для прошедших и неподдерживаемых встреч показывается
информационная карточка. На странице честно указано, что готового вердикта
в публичном HTML нет: пользователь переходит в сервис и запрашивает разбор.
Там действуют прежние условия авторизации, оплаты и списания одной единицы.
Никаких исключений для User-Agent поискового робота или обхода платного доступа нет.

SSR-обход не вызывает Qwen, не создаёт задания статистики/автоанализа и
не читает event_analyses. Личные заметки, купленные ответы, участник-предпочтение
ИИ и пользовательские данные не публикуются. Это одинаковая открытая страница
для человека и поисковика, не полная платная статья с доступом только для бота.

Каталог `/matches/` имеет обычную HTML-пагинацию и ссылки. На главной есть
ссылка на каталог; карточки и карусель используют публичные URL как href,
сохраняя обычное открытие внутри приложения при простом клике. Новые вкладки,
копирование ссылки и роботы переходят на серверную страницу.

Источник списка — постоянные archive_headers и старые карточки сборщика,
с объединением по event ID. Исчезновение из текущего фида не удаляет страницу.
Подтверждённый итог берётся через существующую привязку архива; одно прошедшее
время не считается доказательством завершения. Результаты без сохранённой
карточки и event ID отдельного URL пока не получают. Настольный теннис,
киберспорт, пустые карточки и события без двух участников/даты исключены.

`/sitemap.xml` — индекс карт сайта. Матчи разделены по 5 000 URL; отдельно
перечислены главная и страницы каталога. `robots.txt` указывает sitemap и
исключает API, сохраняя доступ к CSS/JS. Служебные переходы `/go/winline/`
возвращают `X-Robots-Tag: noindex, nofollow` и не блокируются в robots.txt,
чтобы поисковик мог прочитать заголовок и обработать перенаправление.
Внешних кнопок перехода больше нет. Старый служебный маршрут ведёт только на собственную страницу матча; в sitemap включены только наши страницы.
Lastmod не выдумывается
из времени последнего опроса коэффициентов. Метаданные каталога кэшируются
на минуту; карты сайта разрешено кэшировать на пять минут. Новые матчи попадают
в sitemap автоматически, без генерации текста нейросетью.

## Выкат и поисковые кабинеты

На VPS сайта: `git pull --ff-only origin main` и `sudo systemctl restart matchlab.service`.
Используется PUBLIC_ORIGIN, по умолчанию `https://prognozich.online`, не заголовок
Host. Существующий Nginx проксирует новые пути через location /; менять службы
нейросети, сборщик и конфигурацию домена не требуется.

Проверить ответы 200 для `/robots.txt`, `/sitemap.xml`, `/matches/` и одной
страницы матча. Добавить сайт/подтвердить владение в Google Search Console
и Яндекс.Вебмастере. В обоих кабинетах отправить
`https://prognozich.online/sitemap.xml`, затем проверить несколько URL инструментом
проверки/переобхода. Добавление sitemap и доступный HTML не гарантируют индексацию
всех страниц, сроки, позиции или точную формулировку поискового сниппета.
Полезность и уникальность сведений на страницах важнее количества URL.

## Если в Google уже появились ссылки /go/winline/

Это старые служебные адреса. Сейчас они ведут только на собственные страницы матчей, а не на сторонний сайт. Раньше
`Disallow: /go/` запрещал обход, но сам по себе не запрещал показывать
обнаруженные URL в поиске. При этом робот не мог прочитать ответ редиректа.
Не возвращайте этот Disallow вместе с новым noindex: правило снова скроет
заголовок от робота. Переход остаётся одинаковым для людей и поисковиков.

После выката:

1. Проверить `curl -sSI 'https://prognozich.online/go/winline/17096175?source=stream'`:
   ожидаются 302, Location на наш `/match/{id}/{slug}` и
   `X-Robots-Tag: noindex, nofollow`. Проверить новый robots.txt.
2. В подтверждённом Google Search Console открыть «Удаления», создать
   временный запрос для **всех URL с префиксом**
   `https://prognozich.online/go/winline/`. Не удалять весь домен, `/match/`
   или `/matches/`. Запрос временно скрывает старые результаты; окончательное
   обновление индекса зависит от повторного обхода Google.
3. Отправить актуальный sitemap и запросить индексирование `/matches/` и
   нескольких настоящих `/match/{id}/{slug}` через проверку URL.
   Для этих страниц ожидаются 200 и canonical на наш домен.

Отчёты «Страницы» и проверка конкретных URL покажут фактическое состояние.
Сам по себе заголовок на редиректе не гарантирует моментальное исчезновение
ранее проиндексированных ссылок или появление новых страниц.
См. [документацию Google о noindex и robots.txt](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

Проверки выполняются только по SEO-ответам, sitemap, изоляции закрытых данных
и изменённой навигации. Платёжные операции и настоящая генерация ИИ не запускаются.
