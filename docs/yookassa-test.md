# Тестовая ЮKassa и доступ к разборам

Это служебная инструкция проверки интеграции. Публичный сайт переведён на
актуальные коммерческие тарифы/условия; проверочный режим не открывает рабочие платежи.
По умолчанию проверочный checkout доступен только администратору; обычный
пользователь и гость могут прочитать тарифы без регистрации. Реальные ключи
по-прежнему отклоняются. Пакет для заявки: `docs/yookassa-application.md`.
`BILLING_PUBLIC_TESTING=true` предназначен только для явной проверки старого
пользовательского сценария в контролируемой среде: при нём тестовая маркировка
показывается всем. На сайте перед одобрением оставлять false.

Пакеты: 1 / 490 ₽, 5 / 2 190 ₽, 10 / 4 090 ₽. Без срока действия. Открытие
одного сохранённого ответа стоит 1 разбор; повторное открытие бесплатно.
Подготовка ответа баланс не тратит. Неуспешный/ограниченный результат не продаётся.
«Рекомендуем пропустить матч» видно бесплатно, остальная часть подтверждённого
ответа закрыта. Подтверждённые завершённые рекомендации остаются публичными.
Администратор может проверять ответы без списания. Покупательский сценарий со
списанием проверяется обычным аккаунтом в контролируемой среде с явно
включённым BILLING_PUBLIC_TESTING; на публичном сайте он по умолчанию закрыт.

## Установка на VPS сайта

```bash
cd /root/matchlab
git pull --ff-only origin main
.venv/bin/python scripts/configure_yookassa.py
sudo systemctl restart matchlab.service
.venv/bin/python scripts/check_yookassa.py
```

Скрипт запросит Shop ID и тестовый секретный ключ скрытым вводом, сохранит `.env`
с правами 0600 и резервную копию. Перед включением создаётся согласованный
SQLite backup `matchlab-before-billing-*.sqlite3` в каталоге данных; копии `.env`
и базы исключены из Git. Ключи не передаются в командной строке и не
выводятся. Меняются только BILLING_ENABLED, YOOKASSA_SHOP_ID, YOOKASSA_SECRET_KEY.
Модель, сборщик, Whisper/Kokoro и другой проект не перезапускаются.

В кабинете **тестового** магазина ЮKassa укажите URL уведомлений:
`https://prognozich.online/api/billing/yookassa/webhook` и события
`payment.succeeded`, `payment.canceled`, `refund.succeeded`.
При Basic Auth уведомления настраиваются в кабинете, не API webhooks для OAuth.

Дальше под администратором откройте пакеты, создайте проверочный заказ и
завершите оплату на тестовой странице ЮKassa. Публичные тарифы гостю и обычному
аккаунту доступны без возможности новой оплаты.
После возвращения появится подтверждённое начисление и кнопка открытия за 1 разбор.
Вновь откройте тот же ответ и проверьте неизменность остатка. Для пропуска фраза
видна без списания; для объяснения нужна отдельная разблокировка.

## Границы интеграции

- Режим BILLING_MODE=test принимает только ключи `test_` и подтверждает `payment.test=true`,
  Shop ID, валюту RUB, сумму, order_id и user_id. Боевой приём денег запрещён.
  Тестовые начисления изолированы ledger mode=test. Условия проверки опубликованы
  в `/static/legal/test-purchase.html`; согласие и редакция фиксируются в заказе.
- Заказ создаётся до обращения к провайдеру; ключ Idempotence-Key равен ID заказа.
  Ключ создания сохраняется при сетевых ошибках. Через 23 часа без payment_id
  повторный POST не выполняется: гарантия ЮKassa действует 24 часа.
- Webhook не доверяет статусу из тела: выполняет авторизованный GET к ЮKassa.
  Неизвестные уведомления не вызывают API. Сверка после возвращения использует
  тот же путь. Начисления, возвраты и открытия защищены транзакциями и UNIQUE.
- Баланс и открытия находятся на сервере. Закрытый текст не отправляется через
  synchronous explain, jobs, личную историю или публичный detail. Закрытые
  ответы не помещаются в браузер под CSS-блюр. Готовые ответы доступны после
  проверки владельца и entitlement, завершённая публичная история — без оплаты.
  У оплаченных системных ответов есть постоянный доступ вне окна публичных
  результатов за 30 дней; они перечислены в кабинете с пагинацией.
- У ранее выданных ответов сохраняется доступ оригинального владельца. После
  первого включения маркер в БД сохраняет защиту даже при выключении оплаты.
  Уже начисленные единицы можно расходовать при паузе покупок.
- Возвраты: отслеживаются подтверждённые refund.succeeded. Для части суммы
  аннулируется соответствующая доля единиц с округлением вверх; полная сумма
  аннулирует весь пакет. Использованные единицы могут образовать корректировку
  остатка; UI показывает ноль доступных и необходимость обращения в поддержку.
- Данные карты не проходят через приложение. Фискальные чеки и боевые налоги
  не включены: до коммерческого запуска нужны отдельная настройка магазина,
  онлайн-касса/чеки по выбранной схеме, контакты покупателя и коммерческая оферта.

Если потерян ответ создания платежа и webhook не пришёл, найдите тестовый платёж
в кабинете по metadata.order_id и сверьте без новой оплаты:
`.venv/bin/python scripts/check_yookassa.py --payment-id <ID>`.

Проверки API выполняются с фиктивным провайдером. Успех на настоящем тестовом
магазине подтверждается владельцем после безопасного ввода ключей на VPS.

Официальные источники: https://yookassa.ru/developers/using-api/interaction-format,
https://yookassa.ru/developers/using-api/webhooks,
https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing.
